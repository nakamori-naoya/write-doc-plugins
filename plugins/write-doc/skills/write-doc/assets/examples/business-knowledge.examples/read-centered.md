# 業務知識の見本（抜粋）：読み取りが中心の業務

この見本は、読み取りが中心の業務で一つの事実の置き場に迷いやすい箇所だけを、社内のお知らせを社員へ届ける業務を題材に抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 誰のものが対象になるかだけを、計算に書いた

「社員は、自分の部署宛てのお知らせを新しい順に20件ずつ見る」という要求には、どのお知らせがその社員に届くかと、どう見せるかが混ざっている。前者を変えると、届くべきお知らせが届かなかったり、届いてはならないお知らせが届いたりするので、業務の答えである。選び方として計算に書いた。後者（新しい順、20件ずつ）は、変えても届くお知らせの集まりが変わらないので書かず、送り先を報告に回した。

並びや件数でも、変えると誰に何が届くかが変わるなら（上位の数件しか届かない掲示のように）、選択や順位の計算として書く。書くかどうかは、項目の種類ではなく、業務の答えを変えるかで決める。

```markdown
## 前提

### 社員の所属

どの社員がどの部署に所属するかは、人事の業務が決める。この業務は、見る時点の所属を読むだけである。

## 計算

### 届くお知らせ

宛先が全社であるお知らせと、宛先の部署に見る社員が所属しているお知らせのうち、取り下げられていないもの。社員の所属と取り下げの有無は、お知らせを出した時点ではなく、見る時点のものを使う。
```

## どの時点の事実で選ぶかで、答えが割れる所を決めた

異動した社員に、前の部署宛ての過去のお知らせが届くかは、「所属している部署宛て」と書くだけでは決まらない。出した時点の所属で選ぶ答えと、見る時点の所属で選ぶ答えがあり、どちらももっともらしい。計算に時点を書き、採らなかった答えは BDD で打ち消した。

````markdown
### [BDD-003] 異動した社員には、前の部署宛ての過去のお知らせは届かない

```gherkin
Given: お知らせ N-0001 は2026年6月1日に、営業部宛てに出された
  And: 社員 E-0001 は2026年6月1日には営業部に所属し、2026年6月15日に開発部へ異動した
When: 社員 E-0001 が2026年6月20日に、届くお知らせを見る
Then: 届くお知らせに、お知らせ N-0001 は含まれない
```
````

## 除くものを、できない行にしなかった

取り下げられたお知らせや、ほかの部署宛てのお知らせは「見られない」ので、できない行を作りたくなる。しかし、見るというきっかけは成立していて、そのお知らせが対象に入らないだけである。除く条件は計算の中に置き、表には、きっかけへの答えが変わる行だけを残した。制約にも置かなかった。届くお知らせは保存された記録ではなく、見るたびに求める値なので、破れていたら誤りになる記録が無いからである。

状況は持たないと一文で書いた。表は二行で、空いた分を選び方の場合分けで埋めていない。

```markdown
## 制約

### 届くお知らせを見るのは本人

届くお知らせは、その社員本人だけが見る。破れると、部署の中だけに向けた知らせが、所属しない人に読まれる。

## 状況

この業務は状況を持たない。届くお知らせは、見るたびに計算で求める。

## 行動・出来事と判断


| いつ | 誰が | 何をすると | 何が起きる | どの決まりによるか |
|---|---|---|---|---|
| いつでも | 社員本人 | 届くお知らせを見る | 届くお知らせを求める | 社員の所属、届くお知らせ |
| いつでも | 本人でない人 | 届くお知らせを見る | できない。何も変わらない | 届くお知らせを見るのは本人 |
```
