# 業務知識の見本（抜粋）

この見本は、業務知識の資料で判断が分かれやすい箇所だけを、図書館の貸出を題材に抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 業務の話かどうかは、仕組みを変えても残るかで決めた

延滞を利用者へ知らせることは、メールをやめて窓口で伝えても、延滞という事実は残る。そこで残るのは「延滞の貸出がある利用者には貸さない」という決まりだけで、知らせ方は業務の決まりから外した。題材が変わっても問いは同じで、本人確認の仕組みや画面の制御は、仕組みを変えれば消えるので書かない。

> 利用者の登録と利用者カードの発行は利用者登録の業務が、本の受け入れと除籍は蔵書管理の業務が担う。この業務は、登録済みの利用者と所蔵している本を所与として扱う。延滞を利用者へ知らせる手段は、この業務の決まりではない。

## 値は、判断を変えるものだけを業務知識に置いた

貸出上限の5冊と返却期限の14日は、借りられるかと延滞かを変えるので業務の決まりに書いた。延滞にする貸出を探すときの並べ方と一度に探す件数は、どの貸出を延滞にするかを変えないので、品質要求へ出し、置き場だけを一行残した。利用者に見える値でも、並びや表示対象を変えないなら同じ扱いになる。

> 借りられるのは、延滞の貸出が一つも無く、借りている冊数が貸出上限の5冊未満で、その本がほかの貸出中か延滞の貸出に属していないときである。4冊借りていれば5冊目は借りられ、5冊借りていれば6冊目は借りられない。

> 判定日時の日が返却期限の翌日以降で、まだ貸出中の貸出をすべて探す。探した貸出を並べる順と一度に探す件数は、どの貸出を延滞にするかを変えないので、延滞にする処理の品質要求に置く。

## 拒否の BDD は、行いの節の拒む理由と NOTE で結んだ

拒む理由は行いの `####` に名前を立て、拒否の BDD の NOTE がその名前を指す。段落で理由を述べるだけでは、BDD の読み手が根拠へ辿れないからである。行える人が本人だけの行いでは、本人以外の拒否も同じ重さで置いた。所有者ひとりが使う道具なら、他人は業務に登場しないので、この拒否は作らない。

```markdown
#### 拒む理由: 他人の利用者カードで本を借りる

他人のカードで借りると、返さなかったときに責任を負うのがカードの持ち主になり、実際に借りた人に返すよう求められない。
```

### [BDD-004] 他人の利用者カードでは本を借りられない

```gherkin
Given: 利用者 U-0002 は利用者 U-0001 の利用者カードを持っている
  And: 利用者 U-0001 は延滞の貸出が無く、借りている冊数は0冊である
When: 利用者 U-0002 が利用者 U-0001 のカードで本 B-1003 を借りる
Then: 借りられず、貸出は生まれない
  NOTE: Rule: 他人の利用者カードで本を借りる
    Reason: 返さなかったときに責任を負う人が、実際に借りた人と違ってしまう
```

## 同時に起きたときは、勝ち負けを決め、負けた側も拒否として書いた

同じ本を二人が同時に借りると、先に受け付けた一人だけが借りられる。負けた側は「貸出中の本を借りる」で拒まれたのと同じで、利用者から見れば拒否なので、その Then にも NOTE を置いた。項目の段落には、それを示す BDD の番号を書く。ぶつかる判断の無い読むだけの業務なら、この節は「なし」の一文で足りる。

### 同時に起きること: 同じ本を二人の利用者が借りる

先に受け付けた一人だけが借りられる。一冊の本は一つの貸出にしか属さないからである（BDD-013）。

### [BDD-013] 同じ本を二人が同時に借りると一人だけが借りられる

```gherkin
Given: 本 B-1009 はどの貸出にも属していない
  And: 利用者 U-0001 と利用者 U-0003 はどちらも借りている冊数が0冊で、延滞の貸出も無い
When: 利用者 U-0001 と利用者 U-0003 が2026年10月1日に同時に本 B-1009 を借りる
Then: 先に受け付けた一人の貸出だけが貸出中で生まれる
  And: もう一人は借りられず、その人の貸出は生まれない
  NOTE: Rule: 貸出中の本を借りる
    Reason: 後から受け付けた時点で、本はすでに先の一人の貸出に属している
```
