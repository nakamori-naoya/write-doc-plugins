# 強調を媒体へ写す

扱う役は4つ——**要点・キーワード・一言でいうと・要約項目**。**どの役をどこへ当てるかは規律の側が決め、ここはそれを何のタグ・記号にするかだけを決める。**

**どこに当てるかは、書く側の規律が決める。** ここはタグ・記号にするだけ。

## HTML のサンプル

**塗り潰さず、蛍光ペンで線を引いた見た目にする。** 文字全体を色で覆うと行が重くなり、暗い配色では文字が沈む。文字の下半分にだけ半透明の色を乗せる。

```css
mark    { background: linear-gradient(transparent 55%, var(--mark) 55%); padding: 0 .1em; }
mark.kw { background: linear-gradient(transparent 55%, var(--kw) 55%); font-weight: 600; }
```

素の段落。

```html
<p>ジョブの状態は書き込みのたびに全体を読み直して統合する。プロセスが同時に走ると、
先に書いた側の更新が失われるためである。たとえば起動処理と心拍が重なると、
心拍が古い内容で上書きしてしまう。つまり<strong>状態ファイルはロックを取ってから更新する</strong>。</p>
```

強調を当てたもの。

```html
<p><mark>ジョブの状態は書き込みのたびに全体を読み直して統合する</mark>。
プロセスが同時に走ると、先に書いた側の更新が失われるためである。
たとえば起動処理と心拍が重なると、心拍が古い内容で上書きしてしまう。
つまり<mark>状態ファイルは<mark class="kw">ロック</mark>を取ってから更新する</mark>。</p>
```

判断の内訳。

- 1文目は段落の主張なので要点マーカー（R7 相当）。
- 2文目の理由と3文目の具体例には**当てない**（R1: 例そのものには引かない）。
- 4文目は「つまり」の後件なので当てる（R6）。
- 「ロック」は繰り返し使う中心概念なので**初出だけ**キーワード（R11・条件2）。

冒頭要約。**1文書に「一言でいうと」は1つだけ。**

```html
<section class="summary">
  <p class="hitokoto">一言でいうと——<mark>状態ファイルは必ずロック越しに読み書きする</mark></p>
  <ul>
    <li><span class="badge imp">最重要</span> <mark>ロックを取った側だけが解放する</mark>。他プロセスのロックを消さない。</li>
    <li><span class="badge pt">ポイント</span> ロックには<mark>TTL を持たせる</mark>。持ち主が死んでも詰まらない。</li>
  </ul>
</section>
```

| バッジ | 何に付けるか |
|---|---|
| `imp`（最重要） | 定義（R11）、問い（R4）に対する結論 |
| `pt`（ポイント） | 対比（R2・R3）、主張（R5 の本音）、要約表現（R6）から取った要点 |

## Markdown のサンプル

**2色に相当する表現が無い**ため、太字とバッククォートで代替する。色が使えないぶん、**太字を装飾に流用した瞬間に区別が消える**。

上と同じ段落。

```markdown
**ジョブの状態は書き込みのたびに全体を読み直して統合する。**
プロセスが同時に走ると、先に書いた側の更新が失われるためである。
たとえば起動処理と心拍が重なると、心拍が古い内容で上書きしてしまう。
つまり**状態ファイルは `ロック` を取ってから更新する**。
```

冒頭要約。`hitokoto` は引用、バッジは太字の角かっこで代替する。

```markdown
> 一言でいうと——**状態ファイルは必ずロック越しに読み書きする**

- **[最重要]** **ロックを取った側だけが解放する。** 他プロセスのロックを消さない。
- **[ポイント]** ロックには**TTL を持たせる**。持ち主が死んでも詰まらない。
```

Markdown で避けること。

- **見出しの代わりに太字の行を置かない。** 見出しは `#` で書く。目次が壊れる。
- **斜体を強調に使わない。** 日本語では判別しにくく、環境によって出ない。
- **バッククォートをキーワード以外に使わない。** コード片と混ざる場合は、コード片を優先してキーワードは素のままにする。
