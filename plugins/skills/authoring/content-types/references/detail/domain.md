# 業務の型

**業務そのものを正本として書き残す型。** 作りを全部やめても残る決まりだけを持つ。

## 業務知識・コアドメイン

**読み手**: 業務を知る人と、それを形にする人
**目的**: **業務として何が正しいか**を1か所に確定させる
**成功条件**: 業務を知る人が読んで正誤を判断でき、作りを変えても書き直さずに済む

**実現手段を書かない型である。** 画面・保存・境界のやりとり・手順の組み立ては、どれも作り替えれば変わる。変わるものを正本へ入れると、作りを変えるたびに正本が腐り、やがて誰も直さなくなる。

**「業務を知る人が正誤を判断できるか」が唯一の受け入れ条件。** 判断できない文が1つでもあれば、それは業務の言葉になっていない。

### 見出した知識を、全部は書かない

**調べて分かったことを置く場所ではない。** 探索の過程では、業務の決まり以外の知識も大量に出る。画面の作り、保存の形、導入の背景、将来の計画。どれも本当のことだが、**本当であることと、この資料に書くべきことは別である。**

判定は1つの問いでできる。**作りを全部やめても残る決まりか。** 残るなら書く。残らないなら、行き先を決めて外へ出す。

外へ出したものは、完成資料の独立した節へ並べない。執筆中の作業メモで行き先を決め、該当する別資料へ移す。完成資料へ対象外の一覧を残すと、コアドメインの業務知識を読む流れが途切れる。

境目は「なぜ」の向きで見分けられる。**「なぜこの決まりなのか」は書く**（決まりの根拠であり、業務の一部）。**「なぜこの仕組みを作るのか」は書かない**（企画の理由であり、業務の外）。背景を書きたくなったら、それは業務の決まりではない合図である。

### 決まりを先、BDDを後

**BDDは資料の最後にまとめて置く。章のあいだに挟まない。** 抽象と具体を交互に並べると、読み手は「これは決まりなのか、一例なのか」を毎回判断させられる。まとめて置けば、決まりを読み終えてから具体へ進める。

不変条件は2つある。**BDDより上だけを読んで業務の判断ができること。BDDに、上で書いていない決まりが現れないこと。** BDDにしか書かれていない決まりがあれば、それは上の書き漏らしである。

**BDDは飾りではない。** Givenにはアクター、対象、事前状態、条件を閉じる。Whenには業務イベントを置く。Thenには業務結果、次状態、変わる権利・責任を書く。境界値、拒否、権限、同時操作は別シナリオに分ける。

### 状態は、何かが起きたから移る

**状態遷移の矢印には、必ず引き金を書く。** 誰の操作か、何が届いたか、どの時刻が来たか。引き金の無い矢印は、読み手に「いつそうなるのか」を推測させる。

引き金は人の操作だけではない。期限の到来、外から届いた連絡、別の業務での出来事も引き金になる。**時間の経過で移るなら、それも「期限が来る」という引き金として書く。**

図の前に**引き金の一覧**を置く。何をすると何が動くかを先に掴めるので、図が読みやすくなる。

### 記載例を先に読む

**テンプレートだけでは足りない。** テンプレートは節の名前しか伝えない。節をどの粒度で切るか、図を何で描くか、具体例をどこまで具体的に書くかは、埋まったものを見ないと揃わない。

書き始める前に [`assets/examples/domain-rule.example.md`](../../assets/examples/domain-rule.example.md) を全文読む。題材は違っても構造は同じである。**題材の中身を写すのではなく、粒度と書きぶりを写す。**

### 何を、どの節へ書くか

第1部は5つの問いに答える形で並ぶ。**何と呼び、何が起きたと捉えるか**（ユビキタス言語・概念）、**いつでも何が守られるか**（常に守られること）、**どう移り変わるか**（状態）、**誰が何を決められるか**（誰が行えるか・業務ルール）、**条件から何が決まるか**（導出されること）。競合と拒否は、そのあとに置く。

ユビキタス言語は、業務用語と業務イベントを分ける。業務用語は対象・役割・状態の採用語である。業務イベントは、すでに起きて判断・状態・責任を変えた事実である。命令や要求をイベントとして書かない。

**同じ意味の語を併記しない。** 別名一覧は揺れを保存するため、採用語を一つ決め、本文・図・具体例をその語へ統一する。

**人が決めるものと、条件から一意に決まるものを混ぜない。** 前者は業務ルール、後者は導出である。導出は手続きとして書き下す。混ぜると、実装する人が「ここは誰の判断か」を読み取れない。

**同時に起きたときの節は、業務の答えだけを書く。** どちらが通るかは業務の意思決定である。排他の方式が出てきたら、それは作りの話であり、この節から出す。

**決まっていないことを空欄にしない。** 「まだ決まっていないこと」へ理由つきで書く。空欄は「決まっている」と読まれる。
