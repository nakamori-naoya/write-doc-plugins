# author-document

これは、与えられた素材から Markdown 文書を一つ完成させ、指定先へ保存する能力である。
素材の収集、関係者との合意形成、文書の公開、複数成果物の編成は行わない。

## 入力

- `material`: 執筆の根拠となるオブジェクトの配列。1件以上を必須とする。インライン素材は `{kind: text, content: "..."}`、ファイル素材は `{kind: file, path: /absolute/path}` とする。
- `document_type`: `assets/template-examples.yml` の型 slug。省略時は素材と読後ゴールから最も近い型を一つ選ぶ。
- `output_directory`: 新規文書の保存先となる絶対パス。新規作成時に必須。
- `update_target`: 更新する Markdown の絶対パス。更新時に必須。
- `name`: 新規文書のファイル名。新規作成時に必須。
- `references`: 追加で従う資料の絶対パスの配列。任意。

`update_target` があれば更新として扱う。この場合に `output_directory` または `name` もあれば、入力の排他違反として停止する。
`update_target` がなければ新規作成として扱い、`name` は `.md` で終わるファイル名を必須とする。
表にない入力キーは受け付けない。
`material` の `kind`、必須キー、許可されたキーを検査する。未知の `kind` やキー、存在しないファイルパスを本文として解釈しない。
必須入力が欠けた場合や入力形式が違う場合はファイルを変更せず、違反項目を返して停止する。

## 1. 入力と保存先を検査する

ファイル素材と `references` が、読み取り可能な絶対パスか確認する。
更新時は `update_target` が存在する Markdown か確認し、内容を読み取る。
新規作成時は `output_directory` が存在する書き込み可能なディレクトリで、`name` がパス要素を含まない `.md` ファイル名か確認する。
新規作成先に同名ファイルがあれば上書きせず停止する。

すべての検査に成功するまで、ファイルを作成または更新しない。

## 2. 読者と読後ゴールを固定する

`references/core-principles.md` を読む。
素材に明示された主な読み手と、読後にできる判断または行動を一つずつ特定する。
読み手か読後ゴールを素材から特定できない場合は、推測せず一問で確認して停止する。

追加の `references` がある場合はここで読み、素材と同じく構成と内容へ反映する。

## 3. 型と参考資産を選ぶ

型の対応表である [`assets/template-examples.yml`](assets/template-examples.yml) を読み、テンプレートと記載例を解決する。
`document_type` がある場合は対応する `assets/templates/` と `assets/examples/` のファイルを読む。
対応がなければ型を推測せず、利用可能な slug を返して停止する。

`document_type` がない場合は、読後ゴールを最も直接支えるテンプレートを一つ選び、対応する記載例を読む。
複数の型が同程度に該当して成果の構成が変わる場合は、候補と違いを示して一問で確認し、停止する。
テンプレートは必要な論点の案内として使い、素材に存在しない事実を空欄埋めのために作らない。

テンプレートが最終版の SVG を参照する場合は、Markdown の保存名から `<ファイル名から .md を除いた名前>.assets/` を同じディレクトリに割り当てる。
使う SVG ごとに、資産テンプレート、最終ファイル名、Markdown からの相対パスを確定する。
新規作成で同名の資産が存在する場合は上書きせず停止する。
更新で同名の資産が存在する場合は内容を読み、今回更新する SVG だけを変更対象にする。
同じ資産ディレクトリにある別のファイルは変更も削除もしない。

Markdown と最終資産の全保存先を検査し終えるまで、いずれのファイルも作成または更新しない。

対象読者の前提を判断する必要がある場合は、次の読者資産から該当するファイルを一つ読む。

- [`assets/personas/backend-1.md`](assets/personas/backend-1.md): 経験 1 年のバックエンドエンジニア
- [`assets/personas/backend-5.md`](assets/personas/backend-5.md): 経験 5 年のバックエンドエンジニア
- [`assets/personas/pm-1.md`](assets/personas/pm-1.md): 経験 1 年のプロダクトマネージャー
- [`assets/personas/pm-3.md`](assets/personas/pm-3.md): 経験 3 年のプロダクトマネージャー
- [`assets/personas/product-user.md`](assets/personas/product-user.md): プロダクト利用者

対応するペルソナがなければ、入力で明示された読者像だけを使う。

## 4. 構成を決める

冒頭で読者の問いへの答えを示す。
その後は、読後ゴールへ必要な論点だけを依存順に並べる。
呼び出し元が指定した見出しは保持する。
それ以外のテンプレートの節は、読者の判断または行動に必要な場合だけ残す。
重要な前提、境界値、例外、未決事項は、それが判断を変える箇所の近くへ置く。

## 5. Markdown の草稿を作る

`references/visuals-and-tables.md` を読み、本文・表・図の役割を分ける。
中間 YAML や工程状態ファイルは作らない。
保存前の草稿は Markdown としてインメモリで組み立てる。

文章は `references/core-principles.md`、表・図・コード・強調は `references/visuals-and-tables.md` の判断規律を適用する。

## 6. 正確性と読みやすさを推敲する

`references/integrity-check.md` を読み、素材と草稿を照合する。
事実、数値、固有名詞、条件、リンクを根拠へ対応させる。
未検証事項と推定はその状態を明示する。

正確性と推敲は `references/integrity-check.md` の判断規律を適用する。

## 7. 保存して結果を返す

更新時は、入力検査で読み取った `update_target` のうち指定された変更範囲以外を保持して保存する。
新規作成時は、入力検査で確定した `output_directory` と `name` の保存先へ保存する。
最終 SVG がある場合は、確定した資産ディレクトリへ SVG を保存してから、その相対パスを参照する Markdown を保存する。
更新時に最終 SVG を変更する場合は、変更対象として確定した SVG だけを保存する。

保存後にファイルを読み直す。
素材にない断定、重要条件の欠落、壊れたローカルリンク、未置換のプレースホルダーがあれば修正して再確認する。
確認できたら、保存した絶対パスと `completed` を返す。
保存または再確認に失敗したら、変更できた範囲を成功扱いしない。
部分的に保存された Markdown または最終資産があれば、その絶対パスを `reason` に含めて `failed` を返す。

## 成功判定

- Markdown 文書が指定した絶対パスに一つ保存されている。
- 冒頭の答えと本文が、固定した読み手の読後ゴールを支えている。
- 重要な事実・条件・未決事項が素材と対応している。
- 表・図・本文がそれぞれの役割に沿い、同じ説明を重複していない。

## 責務の境界例

- 該当: 既存の調査素材から設計判断を読める Markdown を一つ作り、指定先へ保存する。
- 非該当: 情報源を探索して素材そのものを収集する。素材がなければ不足を返して停止する。
- 境界: 既存文書の更新は一つの完成文書を返すため扱う。複数文書の統合方針を決める仕事は扱わない。
