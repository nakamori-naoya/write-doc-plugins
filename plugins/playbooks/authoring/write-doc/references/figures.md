# 図の要件

## 必須かどうかを決めるのは、この段取りである

解決した設定の `requirements.figures` を読む。値は boolean だけを許し、キーが無ければ同梱の既定値 `false` を使う。

| 値 | 意味 |
|---|---|
| `true` | 主要な主張を理解させる図を最低1つ要求する |
| `false` | 図を必須にしない。図を禁止する意味ではない |

**図を必須にするかは、この文書だけが決める。** 資料かどうかを知っているのは、組み合わせる側だけである。図を選ぶ工程は「この箇所は図にすると速い」を判断できるが、「図が無い成果物を許すか」は判断できない。下段へ必須判定を押し付けない。

図の工程は、関係を理解する助けになる図をすべて選び、候補が無ければ0枚と理由を返す。

## 受け取った結果と照合する

図の工程からは、各図の図の主張・図の型・図の内容と挿入位置が返る。

`true` なのに、本文の主要な主張から選ばれた図が1つも無ければ、保存工程へ進まない。枚数を満たすための飾り図を作らせず、図にできる主張が無いことを報告して止める。飾りで数を満たすと、次からその資料の図は読まれなくなる。

## 画像として返った図

`figures_applied` で `kind: image` の図は、`content` に実ファイルの絶対 path を持つ。ファイルが無い図が1つでもあれば、`state.py fail --step visual` で止めて理由を報告する。生成仕様だけを図の内容として受け取って保存へ進まない。

## 媒体表現は保存先に従う

描き方は媒体側の手引き（doc-render）が持つ。ここで決めるのは「図が要るか」「その図が主張を担っているか」だけである。
