# writing-rules の適用手順

## 読み手ができるようになることから設計する

読み手のメンタルモデルとは、対象の要素・関係・振る舞いについて、読み手が頭の中に作る理解である。品質は章や具体例の数ではなく、その理解を使って文書の目的に沿う説明・判断・行動ができるかで決まる。

1. `reader_context` と、あれば `decisions`（grillで合意した決定と未決）を読み、主な読み手、読む場面、既知のこと、説明が必要なこと、起こりそうな誤解、説明なしで使える用語、読後の到達点を確認する。単独使用なら依頼・資料から同じ内容を短く整理する。根拠のない前提は仮定と記し、目的を変える不足だけ質問する。
2. `path` で経路表を作る。到達点に必要な概念を、足場・導入する節・初めて使う節・図とともに並べる。**この表が本文の順序と長さを決める。** write-doc から呼ばれた場合は `reading_path` として残す。
3. `structure` で冒頭・見出し・末尾・本文に残す情報を決める。テンプレートの節は問いの候補であり、経路に無い節は埋めない。
4. `section` で各節を書く。関係を説明し、必要な箇所へ具体例・比較・図・手順を置く。図は関係を導入する地点に置く。
   自分が観測・計測・推定した値や、その比較を載せるなら `evidence` を適用する。
5. `style` で語と文を整える。同じ理解に至るなら短い方を選ぶ。`emphasis` で拾い読みを補助する。
6. `final-check.md` の問いに、本文だけを根拠に答える。経路表と本文の対応も確かめる。前提の飛躍や誤解が残れば、表現だけでなく経路・構成・範囲まで戻って直す。

読み手に合わせるとは、誤った前提に同意することではない。既存の理解が誤っている場合は、使える部分を足場にし、修正が必要な関係と理由を早めに示す。

作業用の経路表や確認記録を、文書本文へ機械的に挿入しない。短いメールなら数行の整理と確認で足りる。

## 規律の役割

| 規律 | 何を決めるか | 及ぶ範囲 |
|---|---|---|
| `path` | 概念の導入順と、本文の長さ | 文書全体 |
| `structure` | 見出し・冒頭・末尾・本文に残す情報 | 文書全体 |
| `section` | 問いへの答えと、その理解を支える説明 | セクション |
| `emphasis` | 拾い読みで浮かせる内容 | 語・節 |
| `style` | 語り口・文のつながり・用語・密度 | 文 |
| `citation` | 出典の3点セットと日本語訳。緩められない | 出典 |
| `evidence` | 実測・推定の条件、比較できる範囲、値と空欄の意味 | 観測値・比較表 |
| `annotated-code` | コードへ注釈を振るときの規律 | コード |

強調の役は `要点` / `キーワード` の2つである。すべての役を使う義務はない。

## 出典だけは緩められない

`citation` は設定で差し替えられない。出典に言及するなら、どこにあるか、そこに何と書いてあるか、だから何をしたかの3点を揃える。日本語以外の引用には日本語訳を添える。存在しない出典・確認していない出典を書かない。引用画像や抜粋だけを読んだ場合は、その範囲を明記し、書籍全体を確認した扱いにしない。
