# コードに注釈を振る（既定）

**コードを載せた文書の本体は、コードそのものではなく、コードに振った注釈である。**

コードだけ貼っても、読み手は「どこを見ればいいか」が分からない。文章だけで説明すると、読み手は自分でコードを開いて対応を取ることになる。注釈は、その2つを1つの画面で対応させる仕組みである。

## 注釈には用途が2つある

何を分からせたいかで、規律が変わる。どちらの用途かを決めずに書くと、注釈の粒度が途中で入れ替わり、読み手が現在地を失う。

| 用途 | 読み手の問い | 並べる軸 | 注釈が答えるもの |
|---|---|---|---|
| **差分注釈** | この変更で何が変わったのか | 変更の単位 | その行が新規か、変わっていないか、なぜそうしたか |
| **実行順注釈** | この処理はどう動くのか | 呼ばれる順 | その行で何が確定し、どこへ分岐し、何が外へ出るか |

**1つの文書で混ぜない。** 差分注釈の途中に「ここで9件が確定する」が混ざると、読み手はそれが変更点なのか元からの挙動なのか判別できなくなる。

## 共通の規律

**① 掲載は2層に分ける。**

| 層 | 何を載せるか | 注釈 | 置き場所 |
|---|---|---|---|
| **読ませる層** | 読み手に実際に読ませたいコード | 必ず振る | 本文 |
| **参照させる層** | 疑わずに済ませるための残り | 要らない | 付録 |

読ませる層を付録へ送った時点で、その文書は読まれない。本文に無いコードは、載せていないのと同じである。参照させる層に何を置くかは、文書の型が決める。

**② 原典へ戻れるようにし、省いたことを省いた場所で示す。** コードを載せる見出しの直下に、原典の恒久リンク（commit を固定したリンク）を置く。行番号は書かない。行番号は原典側で変わり、本文に写した番号は必ずずれる。読ませる層は選んで載せる。省いた箇所には `…` と原典リンクの印を置く。印が無いと、読み手は載っているものが全部だと読む。生成物・巨大な JSON・mock は読ませる層へ置かない。注釈を振れないものを並べると、注釈密度が薄まり、読み手は注釈を探す読み方をやめる。

**③ 注釈は、説明したい行の直前へ、`▼［区分］理由` の形で差し込む。** コードの前や後ろにまとめて置くと、読み手は本文と表のあいだで目を往復させ、現在地を見失う。`▼` は元のコードコメントと注釈を見分ける印である。

## 差分注釈の規律

**変わっていない行にも注釈を振る。** 注釈が新規の行にしか付いていないと、読み手は画面にある全部が新規だと読む。「この行は旧実装と一字一句同じ」と書いてあることに価値がある。対象は読ませる層に載せた行だけで、各ブロックに最低1つ振る。参照させる層の全行に区分を振る義務は無い。

凡例を文書の冒頭に置く。置かないとこの規律が機能しない。

| 表記 | 意味 |
|---|---|
| ［新規］ | 旧実装に無かった行 |
| ［ロジック変更なし］ | 呼ぶメソッド・条件・引数とも旧実装と同一 |
| ［コメントのみ変更］ | コードは同一で、コメントの文言・配置だけが変わった |
| ［削除］ | 旧実装にあって、今は無い |

注釈は「どの区分で」「なぜそうなのか」を、その行の直前に書く。

```
▼［削除］旧実装が使っていた utility（1/10 の抽選用）。旧ロジックが丸ごと消えたことに伴う
▼［新規］新ロジックの閾値判定に使う
import vote_lower_limit_service
```

## 実行順注釈の規律

**注釈は、その行を通過したときに何が起きたかを書く。** 区分ではなく、状態の変化である。凡例を冒頭に置く。差分の凡例とは別物で、同じ文書に両方を置かない。

| 表記 | 何に付けるか |
|---|---|
| ［入力］ | この段階が受け取った値と、その出どころ |
| ［確定］ | この行を抜けた時点で決まった値 |
| ［分岐］ | 条件と、どちらへ行くか。両方の行き先を書く |
| ［副作用］ | DB・キャッシュ・ログなど、外へ出るもの |
| ［次へ］ | 次にどこを呼ぶか |

**分岐と副作用の行には必ず注釈を振る。** 飛ばすと、読み手は「なぜここで終わったのか」を後から逆算することになる。

**同じことを2度書かない。** 直前の段階で説明した値は、次の段階では参照だけにする（「段階3で確定した cacheKey」）。

**呼び先へ潜るかどうかを、その場で宣言する。** 潜らないなら「ここでは追わない」と書く。書かないと、読み手は続きがあると思って探す。

### 幹を完走してから枝へ降りる

幹は対象処理の主要な制御フローである。幹の途中へ呼び先の詳細コードを挟まない。呼び先の中身を見なくても入出力を説明できるなら、その場には呼び出し行と戻り値の意味だけを置き、詳細は文書下部の枝へ送る。幹に残すのは、その数行を見なければ幹の入出力を説明できない呼び先だけで、残す理由を注釈に書く。

- 幹から枝へは、呼び出し行の注釈にページ内リンクを置く
- 枝の冒頭から、呼び出し元の幹へ戻るリンクを置く
- 枝は幹で初めて呼ばれた順に並べる
- 分岐から複数の実装へ進む場合、実装本体は枝へ置く
- 枝からさらに呼ぶ先は原典リンクで打ち切り、多段の枝を作らない

## 書かないこと（両方に共通）

- **コードを日本語に翻訳しただけの注釈。** 「err が nil でなければ return する」は、コードを読めば分かる。書くのは、その行が処理全体の中で持つ意味である
- **推測した意図。** 原典（コード上のコメント・PR・コミット）に無い理由を書かない。無ければ「言及なし」と書く
- **レビュー意見。** 直すべき点は別の節・別の文書へ分ける。注釈に混ぜると、事実と意見の区別が消える
