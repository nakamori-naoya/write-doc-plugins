# 文章スタイルガイド（既定）

**どういう語り口・粒度で書くか**の規約。差し替えたい場合は `.harness-plugins/writing-rules.config.yml` の `rules.style` に自分のファイルを指す。

## 語り口

- 常体（だ・である）で書く。
- 中身のない前置きを書かない。**1文目から中身を書く。**
- 断定できることは断定する。不確かなものは**何が不確かかを書く**。
- **確認していないことを確認したように書かない。**

## 文の粒度

**段落の割り方は `section` ガイドが決める。ここで決めるのは1文の長さと形である。**

- 結論を先に置く。理由は後ろ。
- **1文で言い切る主張は1つ。** 2つあるなら、そこが句点の位置である。
- **読点で節を3つ以上つながない。** 3つ目を足したくなったら切る。
- **1文は60字を目安に、100字を超えたら必ず切る。** 100字を超えた文には、意味を変えずに切れる場所が必ずある。
- 3項目以上の並列は箇条書きか表にする。
- 表にできるものは表にする。

### 文を伸ばす接続は、句点へ置き換える

**主張を継ぎ足すために使った接続は、そのまま句点へ置き換えられる。** 次の形が出たら、後件を独立した文にする。

| 伸びる形 | 直し方 |
|---|---|
| 「〜であり、〜である」 | 前件で切る。対等な並列なら箇条書きにする |
| 「〜ため、〜である」「〜ので、〜である」 | 結論を1文で言い切り、理由を次の文へ回す |
| 「〜が、〜である」（逆接でない「が」） | 切る。逆接なら `section` ガイドの R10 に従う |
| 「〜として、〜する」「〜しつつ、〜する」 | 動作が2つある。2文にする |
| 「〜こと（もの）は、〜ことである」 | 名詞化をやめ、主語と述語のある文にする |

**主語が変わる連結は必ず切る。** 「A は B であり、C は D である」は2文である。1文へまとめると、読み手は主語をどこまで引き継ぐかを毎回判断させられる。

## 主語・対象・条件・述語を対応させる

**文章は、明示された文脈だけから「誰・何について、何を、どの時点・条件で、どうする／どうなる」が
一意に読めるように書く。** 文法上の主語や目的語をすべての文で機械的に反復するのではなく、意味上の
主体・対象・条件・述語の対応を曖昧にしない。

- 主語・対象・時点・条件を省略できるのは、同じ文、段落、見出し、列見出しから参照先が一意に決まり、
  別の解釈が生じないときだけである。
- 「これ」「同じ」「当日」「扱う」「返す」のような語だけでは主体・対象・結果が定まらない場合、
  具体的な主体名、対象となる値や状態、時点、結果を書く。
- 複数の主体・対象・時点を1つの文や行で扱う場合、それぞれと述語・結果の対応が分かるよう、名前を
  繰り返すか、文・箇条書き・表の列を分ける。
- 各文へ4要素をすべて詰め込む必要はない。その文が述べる関係を、読み手が暗黙の主語や目的語を
  推測せず一意に復元できることを合格条件にする。

この一般則は、仕様、設計、受け入れ条件、具体例にもそのまま適用する。Given/When/Thenは1シナリオ内で
主体・対象・条件・結果の対応を閉じ、別シナリオの暗黙情報を引き継がない。表は列見出しと各行だけで
対応が分かるようにし、前の行や空欄セルを補って読ませない。

## 流し読みへの対応

読み手は全部を読まない。1ページで読まれるのは多くて3割程度。

- **最も重要な情報を冒頭に置く。** ゴールをタイトルに要約し、最初の3段落に要点を入れる。
- 長い塊を割る。見出し・リスト・コールアウトで、流し読める形にする。
- 見出しだけを追って筋が通るようにする。

## 手順の書き方

- **1手順1行動。** 2つの動作を混ぜない。
- 手順ごとに期待結果を書く。
- 手順が10を超えたら、分割するか、対象が複雑すぎないかを疑う。

## 避けること

- 章立てのために内容を薄めること
- 読み手が違う内容を1本に混ぜること
- 「〜と思われる」で断定を避けること
- 秘匿（トークン・PII・マシン固有パス）を載せること
