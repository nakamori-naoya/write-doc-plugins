# write-doc

渡された素材から、読み手が読み終えたら一つの判断か行動へ進めるMarkdown資料を1本書き、指定された場所へ保存する。書き方はすべて[書くときの規範](references/writing-norms.md)に従う。この SKILL が持つのは、素材と資料の境目の判断だけである。

ほかの package からも、人から直接頼まれたときも、下の入力の形に整理してから始める。ほかの package が読んでよいのは、書くときの規範と、各型のテンプレートの冒頭にある「検査が読む目印」だけである。目印は見出しの文言から切り離してあるので、見出しには節の結論を入れてよい。目印を変えるときは、それを読む検査の持ち主と同時に変える。

## 入力

- `material`: 本文の根拠にする素材。1件以上の配列で、各要素は `{kind: text, content: "..."}` か `{kind: file, path: /absolute/path}` である。
- `document_type`: 文書型の名前で、[型の一覧](assets/template-examples.yml)にあるもの。省略してよい。
- `output_directory` と `name`（新しく作るとき）、または `update_target`（書き直すとき）。どちらか一方だけを受け取る。`name` は `/` を含まない `.md` の名前で、日本語も使える。
- `references`: 追加で従う資料の絶対パスの配列。省略してよい。

## 判断の要

**主メッセージを一文で書けなければ、素材が足りない。** 言い回しで埋めず、足りないものを返して止まる。

**素材に無い事実で埋めない。** テンプレートの節は論点を思い出すための案内で、根拠の無い節は置かない。素材にある事実を一般的な知識や論理で分かるように説明するのは、書き足しではなく説明である。素材が推測や未確認なら、そうだと本文に書く。

**読み手と、読んだ後の判断は一つに決める。** 素材に書かれていればそれを使う。書かれていなければ、依頼の文、素材の宛先、文書型から最も筋の良いものを一つ仮に置いて進め、根拠と選ばなかった候補を報告に添える。文書型が渡されていないときも同じで、二つの型が同じくらい当てはまっても止まらない。渡された型が一覧に無いときだけは、型を推測せず止まる。読み手の知識の段階を見極める必要があれば、[読み手の像](assets/personas/)から一人を読む。

**作業の記録は成果物に写さない。** 何を問いにしたか、確認した日や人、外した候補は依頼元への報告に書く。型の読み方（Given / When / Then の意味など）も本文に書かない。それはテンプレートが受け持つ。

**保存先は依頼のとおりにする。** 決まった置き場を補わない。保存するのは、完成したMarkdownと、その資料が参照する最終版の図だけである。

## 手順

1. 入力を確かめる。ファイルの素材と `references` が読める絶対パスか、新しく作るなら同じ名前のファイルが無いか、書き直すなら `update_target` が既存のMarkdownかを見る。確かめ終わるまでファイルを作らない。
2. 書くときの規範と `references` を読み、読み手と読んだ後の判断を決める。
3. 型の一覧からテンプレートと見本を読む。見本は粒度と具体性の見本であり、題材、値、書式の癖は写さない。テンプレートが最終版のSVGを参照する型では、保存名から `.md` を除いた名前に `.assets/` を付けたディレクトリへ置く。
4. 主メッセージと、見出しだけの骨組みを作る。呼び出した側が指定した見出しは残す。
5. 草稿を書き、規範の「書き終えたら、見出しと段落の最初の文だけを読み返す」で骨組みを、素材との突き合わせで事実を確かめる。
6. 図、Markdownの順に保存し、保存したファイルを読み直す。残ったプレースホルダーや執筆の注釈、切れたリンクがあれば直す。書き直しでは、頼まれた範囲の外を変えず、既存の見出し、語り口、ほかの資料から参照されている見出しをテンプレートの見出しへ置き換えない。

## 止まるとき

次のときは `status: failed` と `reason` を返し、ファイルを変えない。

- 入力が上の形に合わない（知らないキー、空の `content`、相対パス、読めないパス、知らない `kind`、保存先の二つの方式が混ざっている、どちらも無い）。
- 文書型が型の一覧に無い。使える名前の一覧を `reason` に入れる。
- 新しく作る資料か図の保存先に、同じ名前のファイルがある。上書きしない。
- 主メッセージを一文で書けるだけの素材が無い。
- 保存か読み直しに失敗した。途中まで保存したファイルがあれば、その絶対パスを `reason` に入れる。

## 出力

成功なら `status: completed` と保存した絶対 `path` を返す。1回の呼び出しで作る資料は1本だけである。仮に置いた読み手、判断、文書型があれば、結果の外の報告に根拠と選ばなかった候補を添える。
