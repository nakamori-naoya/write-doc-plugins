# 学ぶ・使う型

## ハウツーガイド

**読み手**: 目的が明確な人
**目的**: 現実の課題を、特定の手順で解決させる
**成功条件**: その課題だけが解決し、寄り道が無い

課題の解決方法ごとに1文書を作り、1ページで完結させる。冒頭に前提条件を置く。前提条件は非常口でもあり、「たぶん間違った場所にいる」と早く気づける。操作に必要な条件と結果は本文へ残し、深掘り用のリンクは末尾へ寄せる。作業を続行できるか変える条件は、その操作の近くに書く。無関係な例外は網羅しない。

## コンセプトドキュメント

**読み手**: 理解したい人
**目的**: 対象が何を表し、どう関係し、どの条件でどう働くかを理解させる
**成功条件**: 読み手が関係と適用範囲を説明でき、別の場面でも判断できる

1つの文書で説明するコンセプトは1つに絞る。設計意図が確認できれば理由を説明する。確認していない設計意図や、概念の説明に不要な代案比較を足さない。具体的な操作や実装の詳細は、目的に合う別の型へ渡す。議事録・設計文書・ホワイトボードの図・内部文書が情報源になる。
