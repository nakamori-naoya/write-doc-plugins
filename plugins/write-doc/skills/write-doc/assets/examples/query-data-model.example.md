# 図書館の貸出のクエリデータモデル

利用者が自分の借りている本を確かめる読み取り、図書館が延滞にする貸出を探す読み取り、窓口が本を借りている利用者を確かめる読み取りの三つが、コマンドデータモデルの貸出と貸出に起きたことだけで実現できることを確かめる。どれも新しいテーブルや列を要さず、`loans`の状態と返却期限、`loan_base_events`の借りた時点を組み合わせれば、業務知識が決めた表示対象と並び順どおりに返せる。

## 貸出と、借りた時点だけを読む

| 読むテーブル | 持ち主の資料 |
|---|---|
| `loans` | [図書館の貸出のコマンドデータモデル](command-data-model.example.md) |
| `loan_base_events` | [図書館の貸出のコマンドデータモデル](command-data-model.example.md) |

### 借りている本を確かめる

`loans`から、その利用者の`user_number`で、`status`が`lent`か`overdue`の行を選ぶ。返却済みの`returned`の行はここで外れる。並べるのは`due_on`の昇順で、同じ返却期限なら借りた時点の早い順にする。借りた時点は`loans`に無いので、`loan_base_events`の`event_type`が`lent`の行を`loan_id`で結び付け、その`occurred_at`を使う。返すのは、資料番号、返却期限、延滞かどうか（`status`）である。

### 延滞にする貸出を探す

`loans`から、`status`が`lent`で、`due_on`が判定日時の日より前の行をすべて選ぶ。延滞の`overdue`と返却済みの`returned`はここで外れ、返却期限が判定日時の当日の行も外れる。返すのは、貸出と返却期限である。並べる順は業務知識が決めていないので、この資料でも決めない。

### 本を借りている利用者を確かめる

`loans`から、その本の`book_number`で、`status`が`lent`か`overdue`の行を選び、`user_number`を返す。一冊の本の貸出中か延滞の貸出は一つなので、返るのは一行か0行で、並べる順は無い。返却済みしか無い本は0行になり、拒否ではない。

他人の借りている本を確かめる場面は、本人の確認で拒まれ、データを読むところまで届かないので対象外にした。

## 未決

なし

## 物理設計への申し送り

延滞にする貸出を探す読み取りは、返却期限の日ごとに数百から千件を超える行を返す。返却期限と状態で絞る index と、一度に読む件数を物理設計で決める。

## BDD

### [BDD-001] 借りている本が返却期限の近い順に、同じ期限なら借りた順に返る

```gherkin
Given: 利用者 U-0001 は、本 B-1001 を2026年10月1日 10:00に、本 B-1006 を同じ日の11:00に借り、どちらも返却期限は2026年10月15日である
  And: 利用者 U-0001 は、本 B-1002 を2026年10月6日に借り、返却期限は2026年10月20日である
  And: 利用者 U-0001 の本 B-1003 の貸出は延滞で、返却期限は2026年10月10日である
  And: 利用者 U-0001 の本 B-1004 の貸出は返却済みで、利用者 U-0002 は本 B-1005 を借りている
When: 利用者 U-0001 が2026年10月12日に借りている本を確かめる
Then: 本 B-1003、本 B-1001、本 B-1006、本 B-1002 の順に返る
  And: 返却済みの本 B-1004 と、ほかの利用者の本 B-1005 は返らない
```
