# 書くときの規範

この規範は、どの文書型の資料にも共通する書き方である。型ごとの template と見本は、この規範の上に載る。書いてから直すより、書く前と書いている最中に縛るほうが効くので、草稿に入る前に読む。

規範は、すべての文に機械的に当てるルールではない。読み手が少ない手間で理解し、判断できるようにするための判断基準である。規範どうしがぶつかったら、読み手の得になるほうを選ぶ。

## 書く前に、主メッセージを一文で書く

本文に入る前に、この資料で読み手に一番伝えたいことを一文で書く。これを主メッセージと呼ぶ。一文で書けないときは、書き方ではなく素材が足りない。言い回しを工夫して埋めず、足りない素材を依頼元へ返す。

主メッセージが書けたら、次に見出しだけの骨組みを作る。見出しを上から順に読み、それだけで話が通るかを確かめる。通らなければ、本文を書く前に見出しの順番か中身を直す。本文を書いてから構成を直すと、書いた文を捨てることになるからである。

誰が読み、読んだ後に何を判断するか、何をするかも、ここで一つに決める。背景の説明は、その判断に要る範囲に絞る。ただし、なぜその課題があるのか、なぜその選択なのかという文脈は、読み手が納得するのに要るので削らない。

## 見出しには、その節の結論を入れる

「背景」「概要」「処理」のような見出しは、中に何が書いてあるかを教えない。開いて中身を探す手間が大きい節ほど、その節の結論を見出しに入れる。たとえば「## 背景」ではなく「## 発注ミスの大半は手入力から起きている」と書く。

全部の見出しを同じ書式にそろえない。「名詞: 結論」の形で全見出しをそろえると、拾い読みが同じ形の繰り返しになり、かえって機械的に見える。結論の文、問いの形、短いラベルを、中身に合わせて混ぜる。短い節や、名前だけで中身が分かる節はラベルのままでよい。

見出しは本文より強く言い切らない。本文が「未定」と書いていることを、見出しで決まったことのように書かない。

## 因果は地の文で書き、箇条書きは本当に並列なときだけにする

「在庫が減った」「担当者が気づかなかった」「欠品した」を箇条書きで並べると、三つの間の因果を読み手が組み立てることになる。「在庫が減っても担当者が気づかず、そのまま欠品した」と地の文で書けば、書き手がその手間を引き受けられる。

箇条書きを使うのは、項目が同じ形で本当に並んでいて、互いに因果でつながっていないときである。担当者と期日がそれぞれ違う作業の一覧や、同じ軸で比べる候補の一覧がこれに当たる。見出しのすぐ下に箇条書きが三つ以上並んだら、項目の間に「だから」「ところが」で言える関係が隠れていないかを疑う。

段落は一つの話題でまとめ、冒頭の文で何の話かを示す。続く文は、その話題を理解するのに要る理由、条件、例を順に足す。別の話題に移るときは段落を分ける。

## 専門用語は、何をするものかを先に言ってから名前を出す

名前を先に出すと、読み手はまだ持っていない棚にその語を置くことになる。何をするものかを平易に説明してから、「これを〜と呼ぶ」と名前を渡す。たとえば「データを変える処理と読む処理を分けて作る設計を、CQRS と呼ぶ」のように書く。一度決めた名前は、資料の最後まで同じものに使う。

仲間内でしか通じない語は、日本語として素直な言い方に置き換える。次の語は、この repository の周りで使われてきたが、初めて読む人には通じない。

| 内輪の語 | 素直な言い方の例 |
|---|---|
| 正本 | 基準にする資料、元の定義 |
| 公開入口 | 外から呼べる skill |
| 合成 | 組み合わせる、つなぐ |
| playbook | 工程の順番を書いた file |
| Zero-Plumbing | 呼ぶ側が中身の配線を知らなくても使える |
| slug | 型の名前 |

言い換えると意味が変わる語は残してよい。その場合は、初めて出るところで何を指すかを一文で説明する。

## 翻訳調を避ける

英語の文の組み立てをそのまま移すと、文法は正しくても読みにくくなる。次の形は、ほかの言い方ができないかをまず考える。

物を主語にして他動詞で結ぶ文は、人か状況を主語に戻す。「この結果は前提の誤りを示している」は「この結果から、前提が誤っていたと分かる」にする。

「〜することができる」は可能形にする。「短縮することができる」は「短縮できる」でよい。「〜することによって」は「〜して」「〜すれば」にする。「〜という観点から」は「〜で見ると」、「〜を持つ」は「〜がある」にできることが多い。

名詞の前に修飾を何層も重ねない。「多くの企業が導入を進めているが効果を実感できていないという課題を抱える技術」のように名詞に届くまで長い文は、二つ以上の文に割る。ダッシュで文の途中に説明を挟み込む書き方も、括弧にするか文を分ける。

## 語順と読点で、係り受けを迷わせない

長い修飾語を先に、短い修飾語を後に置く。節は句より先に置く。時と場所は、大きい枠から小さい枠へ書く。

読点は、文の構造の切れ目に打つ。長い修飾語が並ぶときはその境目に打ち、切れ目の無いところには打たない。息継ぎのための読点は、読み手に「何が区切られたのか」を探させる。

一つの文には一つのことを書き、主語と述語を近づける。ただし、因果や対比のように一つにつながった考えを、短くするためだけに細切れにしない。文と文の関係を読み手に推測させることになるからである。四十字から六十字は見直しの目安にすぎず、合否の基準ではない。

## 濃淡をつけ、同じ型を三回続けない

全部の節を同じ厚みと同じ文型で書くと、どこが大事かが伝わらない。判断を左右する節は例や数値を添えて厚く書き、言うことが少ない節は短く書く。書くことが無い見出しは置かない。

同じ型が三回続いたら、少なくとも一つは入り方を変える。型とは、「X は〜である」で始まる定義の文、節の中の並べ方（背景、仕組み、条件）、文の書き出しのことである。濃淡は強弱のことで、順番ではない。本当に並列なものに、優先順位を付けない。

## 確かさを言葉で書き分ける

事実は言い切る。推測には「と推定する」「仮に置く」のように推測だと分かる語を付け、確かめていないことには「未確認」と書く。全部の文を「と思われる」でぼかすと、どこが確かなのかが読み手に分からなくなる。

事実には、素材のどこにあるかが分かる参照を添える。素材に無いことを事実として書かない。素材にある事実を、一般的な知識や論理で読み手に分かるように説明するのは、書き足しではなく説明である。

## 削るのは、読み手の判断が変わらない記述だけ

書き手の身を守るためだけの注釈、中身の無い前置き、同じことの言い直しを削る。「本書では〜について述べる」のような書き出しは、何も伝えないので削る。

一方で、読み手が納得するための背景、仕組みの説明、判断を変える条件や例外、平易な言い換えや具体例は削らない。文字数を減らすこと自体を目的にしない。削った後に、判断に要る条件と根拠が残っているかを確かめる。

## 書き終えたら、見出しと段落の最初の文だけを読み返す

本文全体を読み直すと細部に気を取られ、構成の乱れを見落とす。見出しと各段落の最初の文だけを抜き出して、続けて読む。論旨が通るか、開く手間の大きい見出しに結論が入っているか、同じ型が三回続いていないか、節ごとに濃淡があるかを、この骨組みだけで確かめる。確かめられないなら、資料はまだ骨組みの段階で崩れている。
