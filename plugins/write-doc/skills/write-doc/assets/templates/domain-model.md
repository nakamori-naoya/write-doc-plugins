## クラス図

<!-- 書く: この文脈のすべての要素と関係を1枚に描く。集約が多くて1枚では読めないときだけ、集約ごとに図を分け、集約どうしの参照だけを描いた図を1枚足す。
     検査スクリプトはこの記法を構文解析するので、書き方は下の図の中のコメントに従う。 -->

```mermaid
classDiagram
    %% 種別は <<集約ルート>> <<エンティティ>> <<値オブジェクト>> <<ドメインイベント>> のどれか一つ
    %% コマンドは集約ルートとエンティティにだけ +コマンド名(引数) で書く。引数は同じ図のクラスのラベルにする。判定だけの操作とフィールドは書かない
    %% 業務の判断に使う時刻（貸出日時など）は、コマンドが引数で受け取る値のクラスにする
    %% class の直後の識別子は、業務知識の対応表の英名にする（下の Root などは置き場所を示す仮の名前）
    class Root["<集約ルートの語>"] {
        <<集約ルート>>
        +<コマンド名>(<判断に使う値の語>)
    }
    %% ほかの文脈でも使う値は、種別に「・文脈共有」を添える
    class Shared["<ほかの文脈の識別子の語>"] {
        <<値オブジェクト・文脈共有>>
    }
    %% コマンドが通るかどうかを決める値には、その値を成り立たせる業務の語を1行に1つ書く
    class Snapshot["<判断に使う値の語>"] {
        <<値オブジェクト>>
        <業務の語1>
        <業務の語2>
    }
    %% 取り得る値が限られる値には、その値を1行に1つ書く
    class Limited["<区分の語>"] {
        <<値オブジェクト>>
        <値1>
        <値2>
    }
    %% ドメインイベントの中には何も書かない
    class Happened["<ドメインイベントの語>"] {
        <<ドメインイベント>>
    }
    %% *-- は集約の内側にある値、--> は識別子で指す相手、..> はコマンドで受け取るか発するもの
    Root *-- Limited
    Root --> Shared : <何を指すか>
    Root ..> Snapshot : 受け取る
    Root ..> Happened : 発する
```
