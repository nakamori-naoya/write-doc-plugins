# Markdownへの書き出し

完成済みの本文を受け取り、意味上の役をMarkdown表現へ写して保存する。本文の主張、構成、用語、文書型は変更しない。

## 入力

- 完成済みの本文を持つファイル
- 保存するファイル名、または差し替える既存ファイルの絶対パス
- 文書型の識別子
- 明示された保存先。指定がなければ解決済み設定の保存先
- 本文が参照する画像ファイル

本文が空、文書型が未確定、差し替え対象が相対パスまたは存在しないファイルの場合は停止する。

## 表現を決める

意味上の役からMarkdown記法への対応は、次の資料だけを根拠にする。

- [Markdown表現](references/markdown.md)
- [出典](references/citation.md)
- [注釈付きコード](references/annotated-code.md)

見出し、段落、箇条書き、表、コードブロック、強調、図、出典を、本文ですでに確定した役に対応させる。表現上の都合を理由に主張や論拠を追加・削除しない。

## 保存先を解決する

新規作成では、次の優先順で保存先を決める。

1. 依頼で明示された絶対パスのディレクトリ
2. 文書型に一致する設定済みの保存先
3. 設定済みの既定保存先

既存資料の更新では、渡された既存ファイルの絶対パスをそのまま使う。保存先を推測し直さない。

相対設定は作業リポジトリを基準に解決する。絶対設定は作業リポジトリを基準にしない。環境変数、`..`、保存先から外れるsymlinkは拒否する。

## 書き出す

解決済み設定ファイルを使い、次のいずれかを実行する。

新規作成:

```bash
scripts/write-doc.sh --config <解決済み設定の絶対パス> --name <ファイル名>.md --body-file <本文ファイルの絶対パス> --template <文書型> [--output-dir <明示された絶対パス>] --format markdown
```

既存資料の差し替え:

```bash
scripts/write-doc.sh --config <解決済み設定の絶対パス> --target <既存ファイルの絶対パス> --replace --body-file <本文ファイルの絶対パス> --template <文書型> --format markdown
```

新規作成で同名ファイルが存在する場合は上書きしない。既存資料は、明示された差し替え操作の場合だけ更新する。

画像はMarkdownファイルに隣接する`<資料名>.assets/`へ置き、Markdownから相対パスで参照する。差し替え時だけ、同じ資料に属する古い画像集合を新しい集合へ置き換える。

## 完了条件

- 保存結果が`written`または`replaced`である
- 出力ファイルが空ではない
- 新規作成時に既存ファイルを上書きしていない
- 差し替え時に指定された絶対パス以外を更新していない
- 画像参照が隣接する画像ディレクトリを指している

`exists`、入力不備、保存先逸脱、symlink越境、空本文は完了として扱わない。

典型例: 完成済みの設計資料を、文書型に対応する`docs/design`へ新規保存する。すでに同名資料があれば停止する。

似て非なる例: 既存資料の文章を推敲する仕事は対象外である。ここでは推敲済み本文をMarkdownへ写して保存するだけである。

反例: 保存時に見出しを組み替え、論拠を追加する。本文の意味を変えるため拒否する。

境界例: 利用者が既存資料の絶対パスを差し替え対象として明示した場合だけ、同じ場所へアトミックに差し替える。
