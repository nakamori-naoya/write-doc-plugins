# choose-visual

**図の正体は、文章で順に読む関係を、位置・形・面積・個数・距離・線・色へ写して同時に見せることである。** 飾るためではなく、主要な主張を速く正確に理解させるために使う。

## 0. 配布物を確かめる

```bash
BUNDLE_ROOT="${CLAUDE_PLUGIN_ROOT:-/absolute/path/to/this/plugin}"
if [ -d "${BUNDLE_ROOT}/skills/authoring/visual-guidance" ]; then
  PLUGIN_ROOT="${BUNDLE_ROOT}/skills/authoring/visual-guidance"

```

**このコマンドは説明例ではない。必ず実行する。** 失敗したら先へ進まない。

## 1. 図が答える問いを決める

依頼、本文、素材から読み手・目的・主要な主張を取る。文章より図の方が関係を速く理解できる箇所を選び、図が答える問いを疑問文1つで書く。

次をすべて満たす候補だけを残す。

1. 資料の主要な主張へ直接つながる
2. 関係・偏り・境界・変化・波及範囲のいずれかを見せる
3. 位置・形・面積・個数・距離・線・色のいずれかに意味を持たせられる

**条件を満たす候補はすべて図にする。枚数の上限は設けない。** 図の方が速く正確に伝わる箇所を文章のまま残さない。候補が無ければ、図を作らず「図にすると理解が速くなる関係が無い」と返す。図を必須にするかは呼び出し元が決める（write-doc の `references/figures.md`）。

型が固定図を持つ場合（content-types のカタログ「固定図を持つ型」）は、その図の主張・型・内容をテンプレートから受け取り、選び直さない。

## 2. 目的に合う型を選ぶ

[目的別の選択表](references/patterns.md)を読み、問いに合う型を1つ選ぶ。インフラの配置を説明したいのにシーケンス図を選ぶなど、問いと型を取り違えない。

対象がインフラ・モジュール依存・API連携・ドメイン状態・コードの読解のいずれかなら、[技術資料の図](references/technical.md)も読む。

**Mermaid で描くか画像にするかは、このスキルが決める。** [画像で作る技術図](references/image-diagrams.md)の条件に当たる図は画像にし、当たらない図は Mermaid にする。媒体側はこの判断を変えない。

## 3. 図の設計を返す

各図について、次の3役を返す。

| 役 | 返すもの |
|---|---|
| 図の主張 | 図だけを見る人に持ち帰らせる1文 |
| 図の型 | 選んだ型と、その型が問いに合う理由 |
| 図の内容 | 要素、配置、線、強調、凡例と、それぞれが意味するもの |

加えて、本文のどの主張の直後へ挿入するかを指定する。挿入位置は、その関係を本文が初めて導入する地点にする。説明を終えた後にまとめて置かない。本文に無い事実を足さず、数値と名称を本文・原典に一致させる。

画像を選んだ場合は、`図の内容`へ使用する参考画像、キャンバス、固定配置、表示文字列、矢印の意味、Scope・前提・対象外、生成後の照合項目まで書く。画像の実ファイルを作れない図が1つでもあれば、`state.py fail --step visual` で止めて理由を報告する。生成仕様だけを図の内容として返さない。

## 4. 品質を確認する

図案を作った後に[quality.md](references/quality.md)を読み、全項目を確認する。
