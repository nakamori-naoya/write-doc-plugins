# 読み手ペルソナ（同梱5人）

**資料は、誰か一人のために書く。** この5人から一人を選び、その人の知識境界を前提に書く。5人以外を作らない。リポジトリ独自のペルソナは受け付けない。プロジェクト固有の既知・未知は、選んだペルソナを骨格として `reader_context` が実行ごとに埋める。

ペルソナは「経歴」ではなく「どの語を説明なしで使ってよく、どの語には説明が要るか」を持つ。

## 5人

| ペルソナ | ファイル | 一言でいうと |
|---|---|---|
| プロダクトマネージャー1年目 | [pm-1](../assets/personas/pm-1.md) | 技術用語が一つも通じない。前提を何も置けない |
| プロダクトマネージャー3年目 | [pm-3](../assets/personas/pm-3.md) | 数字で判断する。関わった範囲の技術語だけ分かる |
| バックエンドエンジニア1年目 | [backend-1](../assets/personas/backend-1.md) | 担当範囲のコードは読める。設計と運用は知らない |
| バックエンドエンジニア5年目 | [backend-5](../assets/personas/backend-5.md) | 設計から運用まで通せる。専門外は「言われれば分かる」 |
| プロダクトの利用者 | [product-user](../assets/personas/product-user.md) | 社内の文脈を一切持たない。画面の語だけ知っている |

## 知識の3段階

各ペルソナは、語を3つの段階へ分けて持つ。判定に使うのは「その人がその語を説明できるか」だけである。リポジトリにコードがあることを根拠に段階を上げない。実装が存在することと本人が理解していることは別である。

| 段階 | 資料での扱い |
|---|---|
| 実務で使える | 説明なしで使う |
| 言われれば分かる | 初出で一言添える。説明なしで論の土台には使わない |
| 知らない | 目的と前提から説明する。使わずに済むなら使わない |

「言われれば分かる」を「実務で使える」へ寄せると、説明が省かれて論が飛ぶ。「知らない」へ寄せると、要らない解説が付いて膨らむ。

## 選び方

1. その資料を読んで判断・行動する人を一人選ぶ。決裁者と実行者が違うなら、本文が誰の到達点を支えるかで決める。もう一方に必要な内容は、別の資料として分ける。
2. 社外へ出す資料は「プロダクトの利用者」を選ぶ。ほかの4人は社内の文脈を持っているので、社内語の混入を検出できない。
3. 候補が2人以上残るなら、知識の少ないほうを選ぶ。少ないほうへ書いた資料は多いほうにも通じるが、逆は通じない。

型がペルソナを決めるのではない。同じ型を、違うペルソナ向けに書き分ける。READMEを「バックエンドエンジニア1年目」向けに書くことも、「プロダクトの利用者」向けに書くこともある。
