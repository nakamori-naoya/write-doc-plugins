# トラブルシューティングの見本（抜粋）

この見本は、トラブルシューティングの資料で判断が分かれやすい箇所だけを抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 見出しは、読み手が見た症状で立てる

読み手は原因を知らずに来るので、見出しを画面に出た文言にした。原因名で見出しを立てると、読み手は自分がどれに当たるかを選べない。

> ## 「この利用枠は予約できません」と表示される

## 原因が特定できないときは、未特定と書き、区別する手を示す

この症状は二つの原因のどちらかで、表示だけでは区別できない。推測で一つに決めず、未特定と書いたうえで、区別できる確かめ方を添えた。原因が一つに決まる症状なら、その原因を言い切る。

> **原因**: 未特定である。空き状況を開いた後に別の予約が成立したか、自分が既に作った仮押さえと重複しているかのどちらかで、占有表示だけでは区別できない。予約一覧で自分の仮押さえを確認すると、この2つを区別できる。

## 対処は、見つかった状態ごとに次の一手と解消の見分け方を組にする

同じ症状でも、見つかった状態で次の一手が変わるので、状態ごとに行を分け、解消したと分かる表示を並べた。

| 見つかった状態 | 次にすること | 解消の見分け方 |
|---|---|---|
| 同じ顧客の、期限内の仮押さえ | その予約の確定へ進む | 同じ予約IDの状態が「確定」になる |
| 有効な自分の予約はなく、希望枠が埋まっている | 最新の空き状況から別の枠を選ぶ | 新しい予約IDと仮押さえ期限が表示される |

## 意図した挙動は、再発防止を「なし」と書く

部分予約を残さないのは意図した挙動なので、防ぐ手を作らず「なし」と理由を書いた。

> **再発防止**: なし。競合時に部分予約を残さないための意図した挙動である。
