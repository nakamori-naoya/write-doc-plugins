# 希望に合う出張手配を確定するE2E BDDシナリオ

> これは [`e2e-bdd-scenarios.md`](../templates/e2e-bdd-scenarios.md) の記載例である。
> TripPaletteは、出張者と手配担当者が移動と宿泊を調整する架空のサービスである。
> 個々の業務ルールや実現方法ではなく、出張者の目的が複数のインタラクションを通じて満たされるまでを示す。

- **型**: E2E BDDシナリオ
- **ユーザー**: 出張者
- **目的**: 出張条件に合う移動と宿泊を選び、出張手配を確定する
- **開始地点**: 出張者が訪問先、到着期限、帰着期限、宿泊日を把握している
- **最終地点**: 移動と宿泊の手配が確定し、出張者と手配担当者が同じ内容を確認できる
- **完了条件**: 出張者が訪問予定を満たす移動と宿泊の確定内容を確認できる
- **確認日**: 2026年8月27日
- **確認した人**: 出張者代表、手配担当者

# ストーリー概要

出張者は、訪問予定を守れる移動と宿泊を手配するため、訪問先と時間条件を伝える。候補を受け取った後、自分の都合と会社の条件を満たす組み合わせを選ぶ。手配担当者との確認を経て内容が確定し、出張者が最終的な移動と宿泊を確認できたところで目的を達成する。

# インタラクション

## 場面 1: 出張条件を共有する

```gherkin
Given 出張者が訪問先と訪問開始時刻を把握している
And 出張者が帰着期限と必要な宿泊日を把握している
When 出張者が手配担当者へ出張条件を伝える
Then 手配担当者が候補を探すために必要な条件を確認できる
And 出張条件に合う移動と宿泊を選べる状態になる
```

**接続**: 確認された出張条件を、候補を提示する場面の前提として受け取る。

## 場面 2: 条件に合う組み合わせを比較する

```gherkin
Given 手配担当者が確認した出張条件がある
When 手配担当者が条件に合う移動と宿泊の組み合わせを提示する
Then 出張者が各候補で訪問予定を満たせるか比較できる
And 出張者が希望する組み合わせを選べる状態になる
```

**接続**: 比較できる候補を、出張者が希望を選ぶ場面の前提として受け取る。

## 場面 3: 希望する組み合わせを選ぶ

```gherkin
Given 出張者が条件に合う候補を比較できる
When 出張者が希望する移動と宿泊の組み合わせを選ぶ
Then 手配担当者が確定対象の組み合わせを確認できる
And 出張者と手配担当者が同じ内容を確定候補として扱える
```

**接続**: 双方が確認した確定候補を、手配を確定する場面の前提として受け取る。

## 場面 4: 出張手配を確定する

```gherkin
Given 出張者と手配担当者が同じ確定候補を確認している
When 手配担当者が移動と宿泊の手配を確定する
Then 出張者が確定した移動と宿泊を確認できる
And 訪問予定を満たす出張手配が確定している
```

**接続**: 最終地点と完了条件を満たし、このストーリーは終了する。

# 既知の分岐

| 分かれる場面 | きっかけ | その後 | 最終地点への影響 |
|---|---|---|---|
| 場面2 | 提示された組み合わせでは出張者の都合を満たせない | 出張者が調整できる条件を伝え、場面2で別の組み合わせを比較する | 最終地点は変わらない |
| 場面4 | 確定候補の一部を確定できない | 手配担当者が確定できなかった内容を伝え、場面2へ戻る | 別の組み合わせが確定するまで到達しない |

# まだ決まっていないこと

- 出張者が移動だけを先に確定したい場合、同じストーリーの分岐として扱うか、別の目的として扱うか。確認先は出張業務責任者である。
