# プロダクトマネージャー1年目

プロダクトの仕事を始めて1年。決まったことを受け取り、進める側にいる。

## 実務で使える

**説明なしで使ってよい語である。**

- 日常の業務語: 会議、議事録、スケジュール、担当、期限、合意
- 自社プロダクトが何をするものか、誰が使うか
- 表計算とドキュメントツールの操作
- 関係者へ確認して回ること

## 言われれば分かる

**初出で一言添えれば通じる。説明なしで論の土台には使えない。**

- リテンション、継続率、チャーンといった指標の名前（**聞いたことはあるが、自分で仮説を立てて判断した経験は無い**）
- リリース、バグ、仕様といった開発現場の語
- 画面、機能、ユーザーといった粒度の語

## 知らない

**目的と前提から説明しないと通じない。**

- プログラミングの一切。Git も GitHub も使ったことがない
- API、データベース、サーバー、インフラ
- 開発の進め方、環境の分かれ方、リリースの仕組み
- デザインの考え方と用語
- 指標を組み合わせて仮説を立て、検証する手順

## この人へ書くときに落ちやすいところ

- **この人は、この配布物のペルソナの中で最も前提が置けない読み手である。** ここを通った資料は、社内の誰にでも通じる。
- **技術用語を1つでも説明なしに置くと止まる。** 「API を叩く」「DBに入れる」は通じない。
- **指標の名前を出して、それが何を表すかを書かない。** 名前は知っているが、何が上がると何が良いのかまでは繋がっていない。
- **この人へ技術的な内容を渡そうとして資料が長くなるなら、それは長さの問題ではなく、読み手の選択が間違っているサインである。**
