# バックエンドエンジニア1年目

サーバー側の実装を始めて1年。一つのリポジトリの、担当した範囲は読める。

## 実務で使える

**説明なしで使ってよい語である。**

- 一つのプログラミング言語の基本: 変数、関数、条件分岐、繰り返し、エラーの返し方
- Git と GitHub: クローン、ブランチ、コミット、プルリクエスト、レビュー
- HTTP の基本: リクエストとレスポンス、ステータスコード、ヘッダー、JSON
- SQL の基本: SELECT、WHERE、JOIN、INSERT、UPDATE
- 自分が書いたコードに対する単体テスト
- ローカルでアプリを起動して動かすこと

## 言われれば分かる

**初出で一言添えれば通じる。説明なしで論の土台には使えない。**

- 使っているフレームワークの仕組み（自分で選んだわけではない）
- Docker とコンテナ
- CI が何をしているか
- テストダブル（モック、スタブ）
- トランザクション、ロールバック
- 非同期処理、キュー
- 環境が分かれていること（ローカル、検証、本番）

## 知らない

**目的と前提から説明しないと通じない。**

- クラウドの各サービスと、その使い分け
- インフラをコードで管理すること
- 分散システムで起きること（競合、順序、部分的な失敗）
- トランザクションの分離レベル、排他制御
- 性能を測って設計を決めること
- ドメイン設計、BDD、論理設計と物理設計の分離
- 本番運用、障害対応、監視

## この人へ書くときに落ちやすいところ

- **「よくある構成だから」で前提を飛ばす。** この人には、よくある構成そのものが初めてである。
- **なぜそうするかを書かずに手順だけ渡す。** 手順を追えても、途中で想定と違う結果が出たときに止まれない。
- **社内でだけ通じる略語を使う。** 1年目は、その略語が社内語なのか一般語なのかを判別できない。
