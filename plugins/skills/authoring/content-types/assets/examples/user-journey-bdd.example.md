# 希望に合う出張手配を確定するユーザー目的達成BDD

> これは [`user-journey-bdd.md`](../templates/user-journey-bdd.md) の記載例である。
> TripPaletteは、出張者と手配担当者が移動と宿泊を調整する架空のサービスである。
> 個々の業務ルールや実現方法ではなく、出張者の目的が複数のインタラクションを通じて満たされるまでを示す。

- **型**: ユーザー目的達成BDD
- **ユーザー**: 出張者
- **目的**: 出張条件に合う移動と宿泊を選び、出張手配を確定する
- **開始地点**: 出張者が訪問先、到着期限、帰着期限、宿泊日を把握している
- **最終地点**: 移動と宿泊の手配が確定し、出張者と手配担当者が同じ内容を確認できる
- **完了条件**: 出張者が訪問予定を満たす移動と宿泊の確定内容を確認できる
- **中心の問い**: 複数の役割をまたいでも出張者の目的達成が途切れずつながるか
- **Journeyとして扱う理由**: 四つの意味ある場面が状態を受け渡し、観測可能な完了へ進むため
- **Journeyに含めない問い**: 予約成立の個別規則、保存構造、各接点の感情評価、操作手順、テスト実行
- **確認日**: 2026年8月27日
- **確認した人**: 出張者代表、手配担当者

# Journey概要

出張者は、訪問予定を守れる移動と宿泊を手配するため、訪問先と時間条件を伝える。候補を受け取った後、自分の都合と会社の条件を満たす組み合わせを選ぶ。手配担当者との確認を経て内容が確定し、出張者が最終的な移動と宿泊を確認できたところで目的を達成する。

# 場面

この記載例では、次の一件を最後まで追う。訪問先は大阪支社、訪問開始は2026年10月14日 10:00、帰着期限は同日20:00、宿泊は2026年10月13日の1泊である。

## 場面 1: 出張条件を共有する

```gherkin
Given: 出張者が訪問先を大阪支社、訪問開始を2026年10月14日 10:00と把握している
  And: 出張者が帰着期限を2026年10月14日 20:00、必要な宿泊を2026年10月13日の1泊と把握している
When: 出張者が手配担当者へこの出張条件を伝える
Then: 手配担当者が訪問先、訪問開始、帰着期限、宿泊日の4つを確認できる
  And: 確認された出張条件が、候補を探す前提として渡る
```

**接続**: 確認された出張条件を、候補を提示する場面の前提として受け取る。

## 場面 2: 条件に合う組み合わせを比較する

```gherkin
Given: 手配担当者が場面1の出張条件を確認している
When: 手配担当者が候補Aと候補Bを提示する
Then: 出張者が候補Aで訪問開始と帰着期限を満たせることを確認できる
  And: 出張者が候補Bでも訪問開始と帰着期限を満たせることを確認できる
  And: 比較できる候補が、希望を選ぶ前提として渡る
```

候補Aは2026年10月13日 18:00発の列車、大阪駅前のホテルに同日宿泊、2026年10月14日 17:30発の帰路である。候補Bは同日20:00発の列車、空港近くのホテルに同日宿泊、2026年10月14日 18:30発の帰路である。

**接続**: 比較できる候補を、出張者が希望を選ぶ場面の前提として受け取る。

## 場面 3: 希望する組み合わせを選ぶ

```gherkin
Given: 出張者が候補Aと候補Bを比較できる
When: 出張者が候補Aを希望として選ぶ
Then: 手配担当者が候補Aを確定対象として確認できる
  And: 出張者と手配担当者が候補Aを同じ確定候補として扱える
```

**接続**: 双方が確認した確定候補を、手配を確定する場面の前提として受け取る。

## 場面 4: 出張手配を確定する

```gherkin
Given: 出張者と手配担当者が候補Aを確定候補として確認している
  And: 候補Aの列車と大阪駅前のホテルがどちらも手配できる
When: 手配担当者が候補Aの移動と宿泊をまとめて確定する
Then: 出張者が2026年10月13日 18:00発の列車、大阪駅前のホテルの同日宿泊、2026年10月14日 17:30発の帰路を確定内容として確認できる
  And: 訪問開始2026年10月14日 10:00と帰着期限20:00を満たす出張手配が確定している
```

**接続**: 最終地点と完了条件を満たし、このJourneyは終了する。

## 場面 4b: 一部だけ確定できるときは確定しない

場面4と同じ前提から、宿泊だけが手配できない条件を外した場合である。**成功する場面から、検証したい一条件だけを外している。**

```gherkin
Given: 出張者と手配担当者が候補Aを確定候補として確認している
  And: 候補Aの列車は手配できるが、大阪駅前のホテルは2026年10月13日が満室である
When: 手配担当者が候補Aの移動と宿泊をまとめて確定する
Then: 候補Aの出張手配は確定しない
  And: 列車だけが確定した状態も残らない
  And: 出張者が、宿泊を手配できなかったことと、次に候補Bを比較できることを確認できる
  NOTE: Rule: 移動と宿泊は、両方を手配できるときだけまとめて確定する
    Reason: 宿泊を手配できないまま移動だけが確定すると、出張者が帰着期限を満たせないまま移動の変更手数料を負うため
```

この規則は出張手配の業務そのものの決まりであり、このJourneyの外にある。別文書で定めている規則を参照する場合は、`NOTE:`の中へ`Source:`としてその文書への相対リンクを置く。

**接続**: 確定しないまま場面2へ戻り、候補Bを比較する。最終地点へは到達していない。

# 既知の分岐

| 分かれる場面 | きっかけ | その後 | 最終地点への影響 |
|---|---|---|---|
| 場面2 | 提示された組み合わせでは出張者の都合を満たせない | 出張者が調整できる条件を伝え、場面2で別の組み合わせを比較する | 最終地点は変わらない |
| 場面4 | 確定候補の一部を確定できない（場面4b） | 手配担当者が確定できなかった内容を伝え、場面2へ戻る | 別の組み合わせが確定するまで到達しない |

# まだ決まっていないこと

- 出張者が移動だけを先に確定したい場合、同じJourneyの分岐として扱うか、別の目的として扱うか。確認先は出張業務責任者である。
