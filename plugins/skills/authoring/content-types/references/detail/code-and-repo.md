# コード・リポジトリまわりの型

## README

**読み手**: リポジトリに来た人
**目的**: これが何かと、最初の一歩を渡す
**成功条件**: 読み手が「自分に関係あるか」を判断でき、関係あるなら次の一歩へ進める

README はリポジトリのチートシートであり、その先のドキュメント群の土台になる。簡潔・有益・正確・最新であること。コードを変えたら README も追随させる。

## 実装解説（PR）

**読み手**: レビュアー、後任、その実装を引き継ぐ人
**目的**: 1つの変更（PR）が何をしたかを、全体の骨格とコード注釈の両方で分からせる
**成功条件**: この1本を読めば、PR の差分を自分で追わなくてもレビューできる

ADR は「なぜそう決めたか」、実装解説は「実際にどう入っているか」である。決定の記録ではなく、入ったコードの案内図である。差分を説明する型であって、処理を実行順に追わせる型ではない。読み手が「この機能はどう動くのか」を知りたいなら、この型では書かない。

本体は「③ 実装の全文」で、読ませる層のコードを選んで載せ、省いた箇所に印を置き、差分注釈を振る。注釈の無い抜粋を貼るだけなら PR の diff を見れば足りる。注釈は変わっていない行にも振り、推測した理由やレビュー意見を混ぜない。
