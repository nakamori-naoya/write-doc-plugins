# 技術資料で頻出する図

## インフラ・実行環境

**問い: 何がどの境界に配置され、どこを越えて通信するか。** 構成図を使う。

- 領域: cloud / region / VPC / subnet / cluster / namespace / trust boundary
- ノード: 利用者、入口、サービス、データストア、外部サービス
- 線: プロトコルと方向。同期・非同期を区別する
- 強調: 障害点、公開境界、暗号化境界、今回の変更範囲

時間順のやり取りが主題でない限り、シーケンス図へしない。

## パッケージ・モジュール依存

**問い: 依存方向と変更の波及範囲はどこか。** 依存関係図または層図を使う。

- 上下または左右を層に対応させる
- 矢印の向きを「利用側→利用先」など凡例で固定する
- 循環、逆向き依存、変更対象を色で強調する
- 全パッケージを載せず、主要な主張に関係する単位へ集約する

## API・イベント連携

**問い: 主体間のメッセージがどの順で交換されるか。** シーケンス図を使う。

- ライフラインは主体に限定する
- request / response / event / retry / timeoutを区別する
- 重要な代替経路だけを `alt` 相当の領域で示す
- 静的な配置や所有境界は別の構成図へ分ける

## ドメイン状態・ライフサイクル

**問い: 何を満たすと状態が変わり、どこへ戻れるか。** 状態遷移図を使う。

- 状態名は名詞、遷移ラベルはイベント＋条件
- 終了、失敗、再試行を省略しない
- 単なる処理手順を状態として並べない

## コードのディープリーディング

主題で分ける。

- 幹と枝の関係 → 幹を太く、枝を接続段階へ配置した構造図
- 条件分岐 → 非自明な判定だけの制御フロー
- 値の生成から確定 → データフロー
- トランザクションや責務 → 背景領域を使う境界図
- 呼び出し主体間の時系列 → シーケンス図

コード掲載そのものは図ではない。図は、掲載コード間の関係を同時に見せる必要があるときだけ使う。
