# 保存する前の読み直し

草稿を保存する前に、事実が素材と合っているか、判断を変える条件が残っているか、読み手が冒頭で答えに届くかを確かめる。どれも、書いている最中には見落としやすいことである。

## 主張の近くに根拠を置く

事実、数値、固有名詞、日付、引用、外部へのリンクを、一つずつ素材と照らし合わせる。読み手が根拠を見分けられるように、主張の近くに素材への参照を置く。原文をそのまま引くのは、正確な文言そのものが判断の材料になるときだけでよく、すべての主張に引用を付ける必要はない。

素材に無いことを、事実として書き足さない。推測、仮説、まだ確かめていないことは、そうだと書き、どう確かめるかも添える。ただし、出典、観測した時点、確認先のような追跡のための情報を一文ごとに挟むと、読み手の考えの流れが切れる。段落の末尾、表、節の末尾の追跡の欄にまとめる。

素材にある事実を、一般的な知識や論理で分かりやすく説明することは、書き足しではない。書き足しを恐れて、説明まで削らない。

## 判断を変える条件を残す

境目の値、当てはまる条件、範囲、例外、期限、単位は、省くと読み手の判断が変わる。短くするために削らない。数値には、単位と測った条件を近くに書く。

## 資料の中で食い違わない

同じものの名前、状態、数値は、資料の最初から最後まで同じにする。本文と表と図と code が、同じことを指しているかを突き合わせる。相対リンクと添付した資産が、保存先からたどれるかを確かめる。template の placeholder や執筆の注釈は、成果物に残さない。

## 読み手の立場で、冒頭と骨組みを読む

冒頭だけで、資料の答えと範囲が分かるかを確かめる。次に、見出しと各段落の最初の文だけを続けて読み、話が通るかを確かめる。読み手が、次の判断か行動に要る条件を見つけられるかも見る。

答えられない問いが素材の不足から来ているなら、推測で埋めない。未決として書くか、資料が成り立たないなら、足りない情報を返して止まる。

## 削った後に、意味が残っているかを見る

重なりや言い直しを削ったら、大事な条件と根拠が残っているかをもう一度見る。納得の足場になる背景、仕組みの説明、平易な言い換え、例は、文字数を減らすためには削らない。文章の量や削った割合は、良し悪しの目安にならない。読み手が理解し、判断し、行動できるかで決める。
