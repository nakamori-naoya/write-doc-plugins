# 品質要求の見本（抜粋）

この見本は、品質要求の資料で判断が分かれやすい箇所だけを、会議室の予約サービスの題材から抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 同じ具体の値でも、合意が無ければ仮説に戻す

重複予約を残さないことは事業責任者が合意したので合意にした。800ミリ秒は観測点、統計量、時間窓、母集団まで揃っているが、決める人の合意が無いので仮説のままにした。負荷の値は利用負荷の ID で引き、ここに書き写さない。

| ID | 守る性質 | 観測・検証 | 根拠と状態 |
|---|---|---|---|
| QR-001 | 同じ利用枠に成立予約を一件だけ残す | 同時予約試験で重複件数が0件 | REQ-002、WL-002、agreed_decision |
| QR-002 | 検索の95%を800ミリ秒以内に返す | WL-001 のピークを10分間与える | REQ-002、WL-001、hypothesis |
| QR-OQ-001 | 月間可用性の目標 | 年末繁忙期の扱いと停止損失を確認する | WL-OQ-001、open_question |

## 語られなかった区分も、関係するかで評価する

可用性は依頼で話題にならなかったが、予約の成立が止まれば利用者が会議室を使えないので、関係はあり答えが無い区分として未決に置いた。話に出なかったことは非該当の理由にならない。

## 頻度の制限は、値が無くても置き場をこの資料に決める

利用者ごとの上限はこの資料が持つが、値の根拠がまだ無い。推測の値を置かず、決めるのに使う観測を添えて未決にした。上限を超えたときに拒むか遅らせるかは、守る結果から決めた。

> 集中時も重複予約を成立させず、処理能力を超えた要求は待ち続けさせずに拒否として返す。利用者ごとの予約要求の上限はまだ無く、集中時に拒否した件数の観測から決める。

## 一覧から外すことと、消去することを分ける

> 予約者の通常一覧では、利用日の翌月末を過ぎた予約を表示対象から外す。これは物理削除の期限ではない。予約事実の保持年限は法務確認が未完了なので、削除期限を確定しない。
