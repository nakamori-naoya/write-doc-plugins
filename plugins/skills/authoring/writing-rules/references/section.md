# セクションの書き方ガイド（既定）

**構造が決まったあと、各セクションの中をどう書き進めるか**の規約。差し替えたい場合は `.harness-plugins/writing-rules.config.yml` の `rules.section` に自分のファイルを指す。

`structure` ガイドが「何をどの順で並べるか」を決め、このガイドが「その1つ1つをどう書くか」を決める。**書いたものをどう目立たせるかは `emphasis` ガイドが決める。**

## セクションを書く手順

セクションは、上から順に書き下ろさない。次の順で組み立てる。

1. **このセクションで言いたいことを1つ決める。** 2つあるなら、セクションを割るか、段落を割る。
2. **それを1文で書く。** これがセクションの先頭に来る。
3. **その1文を支えるものを足す。** 理由・具体例・数字・図。
4. **具体から抽象へ戻す。** 「だから何が言えるか」を書いて閉じる。

**1文目に主張が来ていないセクションは、まだ組み立てが終わっていない。**

## 段落の作り方

- **1段落1主張。** 2つ言いたいなら段落を割る。
- 段落の先頭に主張、後ろに根拠。逆にしない。
- 主張を**述部を含む1つの節**で言い切れる形にする。言い切れないなら、まだ考えがまとまっていない。
- **1段落は3文が目安、4文が上限。** 5文目を足したくなったら、そこが次の段落の1文目である。
- **割ると決めた段落は、実際に別の段落として渡す。** 同じ塊の中で句点を打っただけでは割れていない。

### 割るかどうかを数えて決める

**「1主張かどうか」は感覚で判定しない。次の3つを数え、どれか1つでも当てはまれば割る。**

| 数えるもの | 割る条件 |
|---|---|
| 文の数 | 5文以上ある |
| 主張の数 | 段落全体を1文で言い直せない。「〜であり、かつ〜」でしか要約できない |
| 役の数 | 答える問いが違う内容（課題／原因／打ち手／求める判断など）が同じ段落へ入っている |

**3つ目が最も見逃される。** 1文ずつは短くても、問いの違うものを並べただけの塊は1段落ではない。

### 役の違う内容を1つの段落へ詰めない

**「課題」「推奨案」「求める判断」は答える問いが違う。** だから同じ段落にも、同じ文にも入れない。**役がN個あるなら段落もN個**になる。

- 悪い形: 「課題は〜であり、推奨案は〜であり、求める判断は〜である」。3つの役が1段落へ入り、読み手が自分で切り直すことになる。
- 良い形: 役ごとに段落を割り、各段落の1文目にその役の結論を置く。役の名前を1文目の頭へ出してよい。

**役が3つ以上あるなら、段落ではなく箇条書きか表にする**（R12）。

## 抽象と具体を往復する

```
【抽象】主張を1文で言う
【具体】実際の値・コマンド・画面・数字で見せる
【抽象】具体から何が言えるかへ戻す  ← ここを省かない
```

3段目を落とすと「例は分かったが結局どうすれば」で終わる。**具体で終わらせない。**

具体は**実在のもの**を使う。作った例より、実際に動かした出力のほうが強い。ただし秘匿は載せない。

## 主張が立つ書き方（読解規則 R1〜R12 の裏返し）

下敷きは[中野芳樹「客観的速読のための現代文読解法一覧」](https://nakanogendaibun.com/wp-content/uploads/2026/05/9db385ece6cb4b91d836bafc7ba5a03a.pdf)。**読む側の規則**であり、たとえば R1 をこう定める。

> 具体例・比喩・引用（「たとえば」「〜のような」「〜など」「〜といった」で導かれる範囲、引用符内） | **要点としない**。その直前または直後にある抽象論を要点とする

**線を引かれる側から見ると、これは「例だけで段落を終えるな」という執筆規則になる。** 例そのものは要点として拾われないのだから、拾わせたい抽象論を例の前か後ろに必ず置くことになる。以下の表は、12個の読解規則すべてに同じ裏返しを当てたもの。

**要点が拾われる形で書く**ための表。同じ R 番号で、**引く側の規則は `emphasis` ガイド**にある。

| | 場面 | こう書く |
|---|---|---|
| **R1** | 具体例・比喩・引用（「たとえば」「〜のような」「〜など」「〜といった」、引用符内） | 具体例の**前か後ろに必ず抽象論を置く**。例だけで段落を終えない |
| **R2** | 否定・比較（「AではなくB」「AだけでなくBも」「AよりむしろB」） | この形で書くなら **Bを言い切る**。Bが弱いなら形ごと変える |
| **R3** | 対比・対照（「Aは〜のに対しBは〜」「〜に比べて」） | 書く前に**どちらが主題か決める**。決まらない対比は書かない |
| **R4** | 修辞疑問（「〜とは何か」「なぜ〜か」） | 問いを立てたら**必ず答えを書く**。答えの無い問いを放置しない |
| **R5** | 譲歩（「たしかに」「もちろん」「なるほど」「無論」） | 「たしかにA」を書いたら**必ず「しかしB」を続ける**。Bが無いなら譲歩ごと削る |
| **R6** | 要約表現（「つまり」「要するに」「結局」「このように」「言い換えれば」） | 「つまり」で始めたら、**その後件に主張の核を置く**。後件を弱く終わらせない |
| **R7** | 重視・強調（「重要」「本質」「前提」「原理」「〜こそ」「実は」「まさに」、最上級） | 「重要」と書くなら、**何がどう重要かまで書く**。語だけ置かない |
| **R8** | 筆者の主観（「〜と考える」「〜べきだ」） | 判断を書くときは**誰の判断か分かる形**にする |
| **R10** | 逆接（「しかし」「だが」「けれども」） | 多用しない。**段落の頭か、文書で最初の1回**を意味のある転換に使う |
| **R11** | 定義・命名（「〜とは…である」「…を〜と呼ぶ」「…を〜と名づける」） | 中心概念は**1回は定義する**。定義できないなら、その概念はまだ整理できていない |
| **R12** | 要点並列（「第一に／第二に」「まず／次に」「一方／他方」） | 3つ以上の並列は、この形か箇条書きにする |

**R9（反語）は採らない。** 原典では「〜ではないだろうか」を強調対象とするが、**テクニカルライティングで反語は使わない。** 読み手は答えを探しに来ているのであって、問いかけを味わいに来ているのではない。番号は原典と対応させるため欠番のままにしてある。

## セクションを書き終えたら

- [ ] 1文目に主張が来ているか
- [ ] 具体で終わらず、抽象へ戻して閉じているか
- [ ] 1段落1主張になっているか
- [ ] **5文以上の段落が残っていないか**
- [ ] **役の違う内容（課題／打ち手／求める判断など）が同じ段落へ混ざっていないか**
- [ ] 立てた問い（R4）に答えているか、譲歩（R5）に本音が続いているか
- [ ] 各段落に**目立たせられる主張がある**か（無いなら削るか書き直す）

目立たせる作業は `emphasis` ガイドへ引き継ぐ。

原典が自ら課す制約も、そのまま引き継いでいる。
