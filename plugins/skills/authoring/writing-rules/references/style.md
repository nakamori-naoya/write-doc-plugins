# 文章スタイル（既定）

**常体で、1文目から中身を書き、主張を言い切り、同じ理解に至るなら短い方を選ぶ。**

この規律が決めるのは、語り口と1文の形である。語の選び方は `terminology`、段落の割り方は `section`、図表文の使い分けと冒頭・見出しは `structure` が決める。

## 語り口

- 指定がなければ、日本語で、常体（だ・である）で書く。使用言語や読み手が明示されたら、その指定に従う。
- 中身のない前置きを書かない。**1文目から中身を書く。**
- **主張は言い切る。** 婉曲な導入、断りの前置き、「〜と言えるかもしれない」「〜と思われる」で主張を遅らせない。
- 断定できることは断定する。不確かなものは**何が不確かか**を書く。
- **確認していないことを確認したように書かない。**

## 文の粒度

- 結論を先に置く。理由は後ろ。
- **1文で言い切る主張は1つ。** 2つあるなら、そこが句点の位置である。
- 100字を超えた文は分ける。100字は表示幅の2〜3行に当たり、主語と述語がそれ以上離れると読み手は対応を保持できない。分けるときは条件と結果の対応を保つ。

### 文を伸ばす接続は、句点へ置き換える

次の形は、前後が別の主張ならその位置で切る。同じ条件と結果、原因と帰結を結ぶ接続は切らない。

| 伸びる形 | 直し方 |
|---|---|
| 「〜であり、〜である」 | 前件で切る。対等な並列なら箇条書きにする |
| 「〜ため、〜である」「〜ので、〜である」 | 結論を1文で言い切り、理由を次の文へ回す |
| 「〜が、〜である」（逆接でない「が」） | 切る。逆接なら `section` の R10 に従う |
| 「〜として、〜する」「〜しつつ、〜する」 | 動作が2つある。2文にする |
| 「〜こと（もの）は、〜ことである」 | 名詞化をやめ、主語と述語のある文にする |

**主語が変わる連結は必ず切る。** 「A は B であり、C は D である」は2文である。

## 量より密度

**同じ理解に至るなら、短い方を選ぶ。** 文章量は品質ではない。書く内容が足りないなら、足りないと書くか、調べて中身を足す。言い換えを重ねて埋めない。

削るのは、同じ主張の言い換え、読み手が実務で使える事項の説明、章立てのために足した文、結論を変えない修飾、同じ観測源の言い換えでしかない根拠（`argument` の独立性を満たさないもの）である。具体例、対照例、図、判断を変える条件は、削らない。削っても読み手の理解・判断が変わらない文・段落は、削る。節の単位は `path` が決める。

## 主体・対象・条件・述語を対応させる

**明示された文脈だけから「誰・何について、何を、どの時点・条件で、どうする／どうなる」が一意に読めるように書く。**

- 主体・対象・時点・条件を省略できるのは、同じ文、段落、見出し、列見出しから参照先が一意に決まるときだけである。
- 「これ」「同じ」「当日」「扱う」「返す」のような語だけでは主体・対象・結果が定まらない場合、具体的な主体名、値や状態、時点、結果を書く。
- 複数の主体・対象・時点を1つの文や行で扱う場合、それぞれと述語・結果の対応が分かるよう、名前を繰り返すか、文・箇条書き・表の列を分ける。
- Given/When/Then は1シナリオ内で対応を閉じ、別シナリオの暗黙情報を引き継がない。表は列見出しと各行だけで対応が分かるようにし、前の行や空欄セルを補って読ませない。

## 手順の書き方

- **1手順1行動。** 2つの動作を混ぜない。
- 手順ごとに期待結果を書く。

## 避けること

- 章立てのために内容を薄めること
- 読み手が違う内容を1本に混ぜること
- 秘匿（トークン・PII・マシン固有パス）を載せること
