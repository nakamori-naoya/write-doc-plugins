# 出す前の確認

**整理した読み手の前提だけを持つ人として本文を読み、本文だけを根拠に答える。** 著者だけが知る情報を補わない。見出しや具体例の数、文字数が揃っただけでは合格にしない。確認項目はこのファイルにだけ置く。

## 1. 読後の判断・行動ができるか

- この文書が何に答え、どこまで答えるかを言えるか。
- 主な対象が何で、何とどう関係するかを本文の言葉で説明できるか。操作・参照が目的なら、必要な手順や項目を見つけて使えるか。
- 読後の到達点に当たる判断・行動を、条件と根拠を添えて示せるか。
- 想定した誤解が本文で解消されているか。冒頭で作った理解を、後半の重要条件で不意に覆していないか。

概念や規則の理解は、掲載例の条件を一つ変えた場面で判断を試す。例の答えを覚えただけでは解けない問いにする。情報が足りない場合に「本文からは判断できない」と範囲を区別できることも、正しい理解である。手順書なら開始条件・次の操作・成功の見分け方・該当する中止条件、参照資料なら項目の所在・意味・利用条件を試す。

答えられない問いや誤答は、欠けた前提、飛ばした関係、紛らわしい例、説明順、対象外へ追い出した重要条件を調べ、構成や範囲から直して、もう一度試す。事実が未確認なら作らず、その範囲を本文で明らかにする。

## 2. 規律ごとの述語

通ったときに言えるのは、その述語が成り立ったことだけである。

**argument**

- 文書の主張が1文で言え、冒頭に前提とともにある。主張が2つ以上あると読める箇所が無い。
- 各節が文書の主張に対する役（根拠・限定・行動）を言える。役を言えない節が無い。
- 各主張に、`verification_means` の手段で確かめられる決定的根拠が1つある。補助根拠は独立で最大2つに収まる。距離・検証可能性を満たさない根拠が無い。
- 反駁・限定・未確認が主張の隣に条件文で置かれている。`stance` が `反対`・`別案を持つ` なら反駁を省いていない。
- `history` の値に従い、時系列と試行の履歴が本文に残っていない（`時系列で残す` の固定区画を除く）。省いた経緯が運んでいた条件が、前提として主張の直前にある。
- 前提のうち、読み手が知らないものが本文にあり、実務で使えるものは無い。

**path**

- 経路表の全行で、初めて使う節が導入する節より前になっていない。足場が無い概念が無い。
- 冒頭が読み手の既知の語だけで書かれ、新しい語はすべて使う前に導入されている。前方参照には節名がある。
- 本文の節と経路表の行が一対一で対応する。図が導入する節にある。

**structure**

- 見出しが主張か問いを言い切り、役割名だけの見出しが無い（固定見出しを持つ型を除く）。見出しだけを追って筋が通る。
- 結論が成果物なら、その実体が冒頭にある。末尾が冒頭や本文の反復になっていない。
- 図にすると速く正確に伝わる関係が、文章のまま残っていない。
- 参照先は実在し、何を補うか分かる。主張の根拠がリンク先へ追い出されていない。

**section**

- 各節が読み手の問いに答え、前の節との接続が入口にある。
- 例・図・表の対象と本文の概念が対応し、例の中にだけ新しい規則が現れない。架空の例に「説明用」の明記がある。
- R2 の B、R4 の答え、R5 の「しかし B」、R7 の「何がどう重要か」が書かれている。R9（反語）が無い。

**style**

- 主張が冒頭の文で言い切られ、前置きや婉曲で遅れていない。確認していないことを確認したように書いていない。
- 削っても理解・判断が変わらない文・段落が残っていない。
- 主体・対象・条件・結果が明示された文脈から一意に読める。表やシナリオも必要な対応を保つ。
- 100字を超える文、主語が変わる連結が無い。
- 手順が1手順1行動で、期待結果を持つ。
- token、PII、machine固有pathを含めていない。

**terminology**

- 本文に出る日常語でない語を1語ずつ確かめ、合格条件の4つのどれかに当たることを言える。「聞いたことがある」を根拠にしていない。
- 用語の説明に別の未説明の専門用語を重ねていない。言い換えで条件や保証範囲を変えていない。コードや画面で照合する名前は正確に残っている。
- 造語には「この文書では〜と呼ぶ」の宣言があり、宣言した語を文書の外で通じる語として扱っていない。

**emphasis**

- 強調の役が要点・キーワードの2つに収まり、装飾のための強調が無い。
- 強調だけを拾い読みしても、主張の適用条件を誤解しない。
- 具体例（R1）そのもの、否定側（R2 の A）、譲歩節（R5 の A）、接続詞そのものを引いていない。
- キーワードが3条件のいずれかに当たり、初出だけで、1文書10語以内である。

**citation**

- 出典すべてにリンクか書誌情報、原文の逐語引用、引用を受けた判断が揃っている。要約は「要約」と書いてある。
- 日本語以外の引用に日本語訳がある。
- 確認していない出典が無く、確認範囲を超えて帰属させていない。リンクが開ける。

**evidence**

- 実測に条件があり、推定に「推定」と幅がある。結論の根拠にした推定には精度がある。
- 表が条件ごとに分かれ、比較できる範囲が明記されている。
- 失敗した回・外れ値・ばらつきと、推奨案が負けている条件・それでも採る理由が残っている。
- 空欄・記号・ゼロの意味が言葉で分かる。未計測の項目に、何をすれば判断できるかがある。

**annotated-code**

- 用途（差分／実行順）が一方に決まり、その用途の凡例だけが冒頭にある。
- 読ませる層が本文にあり、参照させる層が付録にある。注釈が `▼［区分］理由` の形で該当行の直前にある。見出し直下に原典の恒久リンクがあり、省略した箇所に印がある。行番号を書いていない。
- コードを翻訳しただけの注釈、推測した理由、レビュー意見が無い。ファイルパスが開けるリンクである。
- 差分注釈: 読ませる層の各ブロックに、変わっていない行への注釈が最低1つある。
- 実行順注釈: 分岐と副作用の行すべてに注釈がある。潜らない呼び先に「ここでは追わない」がある。幹だけで入口から出口まで通り、幹と枝に往復リンクがあり、枝の中に枝が無い。

## 3. 記録

`reader_review` には、問い・答え・根拠の節・修正した箇所・残る未確認を短く残す。経路表は `reading_path` として別に残す。「全項目OK」だけで済ませない。自己確認と第三者・実際の読者による確認は区別し、行っていない検証を報告しない。
