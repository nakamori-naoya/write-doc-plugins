# writing-rules

**読み手が必要な理解を組み立て、目的の判断や行動ができる文章を書くための規律。** 前提と到達点から構成・範囲を設計し、本文から問いに答えて確かめる。抽象と具体の往復、要約、図や表は必要な箇所で選ぶ。

**媒体を知らない。** HTML なのか Markdown なのかプレーンテキストなのかは決めない。だから資料に限らず使える——PR の説明文、チケット、レビューコメント、メール。

## 使う

```
/write-with-rules      規律に従って書く／直す
```

## 何を持っているか

| 規律 | 何を決めるか | 及ぶ範囲 |
|---|---|---|
| `path` | 概念の導入順と本文の長さ（段階的開示） | 文書全体 |
| `structure` | 見出し・冒頭・末尾・本文に残す情報 | 文書全体 |
| `section` | 各セクションの中をどう書き進めるか | セクション |
| `emphasis` | **どの役をどこへ当てるか** | 語・節 |
| `style` | 語り口・文の粒度・用語 | 文 |
| `citation` | 出典の3点セットと日本語訳（**緩められない**） | 出典 |
| `evidence` | 実測・推定の条件、比較できる範囲、値と空欄の意味 | 観測値・比較表 |
| `terminology` | 語の実在確認、読み手に通じるかの判定、造語の宣言 | 常に |
| `annotated-code` | コードへ注釈を振るときの規律 | コード |

**コード注釈は用途で2つに分かれる。** 差分注釈（この変更で何が変わったか）と実行順注釈（この処理はどう動くか）。**共通するのは「掲載を2層に分ける」「読ませる層は畳まない」「注釈をコードの途中へ差し込む」の3つで、凡例とチェックリストは用途ごとに別。** 実行順注釈ではさらに、主要制御フローの**幹を先に完走**させ、別パッケージの詳細は下部の**枝**へ分けて往復リンクする。

## 強調は2つの役でだけ扱う

| 役 | 何を浮かせるか |
|---|---|
| 要点 | その段落の主張 |
| キーワード | 中心概念の語（初出だけ） |

文書全体の主張と冒頭の要点は、見出しと冒頭の段落が運ぶ。札付きの箇条書きにしない。

**何のタグ・記号へ写すかは決めない。** ここで書式まで決めると、媒体が増えるたびに文章の規律を書き換えることになる。

## 設定

```yaml
# <repo>/.harness-plugins/writing-rules.config.yml
version: 1
rules:
  section: docs/guides/section.md      # 自分のファイルで既定を上書き
  emphasis: docs/guides/emphasis.md
extra: "docs/guides/terms.md, docs/guides/brand.md"   # 自由に足す
instructions:
  writing:
    directive: rulesの各ファイルと適用手順を読み、読み手の前提と到達点からpathで経路表を作り、structure、section、style、emphasis、terminologyを適用し、citation、evidence、annotated-codeを該当時に適用する
```

設定は自己完結させる。repository設定があればpersonalや同梱既定は読まれない。

**指定したのにファイルが無ければ止まる。** 黙って既定へ倒れると、差し替えたつもりで効いていない状態になる。

## しないこと

- 媒体の書式を決めない（タグも CSS も持たない）
- 文書の型を知らない
- **中身を機械で検査しない。** 強調率も語数も引用数も数えない
- **出典の規律は緩められない。** 設定で上書きしても3点セットは外れない
