# セクションの書き方ガイド（既定）

**構造が決まったあと、各セクションの中をどう書き進めるか**の規約。差し替えたい場合は `.harness-plugins/writing-rules.config.yml` の `rules.section` に自分のファイルを指す。

`structure` ガイドが「何をどの順で並べるか」を決め、このガイドが「その1つ1つをどう書くか」を決める。**書いたものをどう目立たせるかは `emphasis` ガイドが決める。**

## 読み手の問いへ答える

各節で読み手が解消したい疑問と、読み終えたときに分かる関係を決める。入口には答えや見通しを置き、理由・根拠・具体の場面で支える。初見では結論の語自体が理解できないなら、短い状況や定義を先に置く。見出しが答えを示している場合は、同じ主張を1文目へ繰り返さなくてよい。

説明では、対象が何かだけでなく、何とどう関係し、条件によって何が変わるかを示す。原因から結果へ進む途中の判断を飛ばしていないか、読み手の既知のことだけで接続できるかを確かめる。名前・視点・時点を変える場合は、切り替わりを伝える。

## 段落は理解のまとまりで区切る

1段落は一つの問いへの答えと、それを理解するための説明をまとめる。別の問いや対象に移ったら段落を分ける。結論と理由、条件と結果はつながりが分かる距離に置く。

3〜4文は長さを見直す目安であり、5文目で必ず切る境界ではない。文が多ければ不要な反復や別の論点の混入を調べる。短文をばらばらに並べても、関係を読み手が補うなら読みやすくなっていない。

比較軸が揃う情報は表、独立した並列項目や行動の順序はリストが役立つ。理由や因果の説明を、項目が3つあるという理由だけで分断しない。

## 理解の飛躍に合う説明を選ぶ

具体例、比喩、比較、図、操作前後の変化は、読み手が関係をつかめない箇所に使う。用語集や短い手順など、目的をすでに満たす説明へ、抽象と具体の往復を追加する必要はない。BDDは条件と結果を比較したいときの選択肢であり、一般の文書へ必須化しない。

具体例を使うときは、できるだけ同じ対象を追い、登場する人物・値・状態が説明中のどの概念に対応するかを伝える。たとえば「仮押さえは15分で失効する」なら、10時に仮押さえした予約が10時15分にどうなるかを示す。その15分が利用時間なのか確定までの猶予なのかも区別できるようにする。

例を理解した読み手が別の条件でも判断できるよう、例が示す規則と適用範囲を結びつける。その結びつきは前後の説明や参照でもよく、毎回「つまり」で抽象論を再掲しない。例の中で新しい規則が現れたら本文へ戻して説明する。例から確かめられない範囲へ一般化しない。

誤解しやすい境界は、条件を一つ変えた対照例で明らかにできる。あらゆる例外の列挙は不要だが、読者の判断を変える条件は主張の近くに残す。比喩は対応する点と対応しない点を区別する。

実際に確認した事例が使えるなら出典とともに使う。架空の例も理解に有効だが、説明用であると明記し、実測・業務上の確定事項・検証済みの出力に見せない。秘匿情報は使わない。

## 主張が立つ書き方（読解規則 R1〜R12 の裏返し）

下敷きは[中野芳樹「客観的速読のための現代文読解法一覧」](https://nakanogendaibun.com/wp-content/uploads/2026/05/9db385ece6cb4b91d836bafc7ba5a03a.pdf)。**読む側の規則**であり、たとえば R1 をこう定める。

> 具体例・比喩・引用（「たとえば」「〜のような」「〜など」「〜といった」で導かれる範囲、引用符内） | **要点としない**。その直前または直後にある抽象論を要点とする

この読解規則は、例と主張を対応させる着眼点として使う。例を含む全段落の末尾を抽象論にする規則ではない。以下は文章を見直す補助であり、上で定めた読み手の理解を優先する。

**要点が拾われる形で書く**ための表。同じ R 番号で、**引く側の規則は `emphasis` ガイド**にある。

| | 場面 | こう書く |
|---|---|---|
| **R1** | 具体例・比喩・引用（「たとえば」「〜のような」「〜など」「〜といった」、引用符内） | 具体例がどの主張を支えるか、本文や参照から分かるようにする |
| **R2** | 否定・比較（「AではなくB」「AだけでなくBも」「AよりむしろB」） | この形で書くなら **Bを言い切る**。Bが弱いなら形ごと変える |
| **R3** | 対比・対照（「Aは〜のに対しBは〜」「〜に比べて」） | 書く前に**どちらが主題か決める**。決まらない対比は書かない |
| **R4** | 修辞疑問（「〜とは何か」「なぜ〜か」） | 問いを立てたら**必ず答えを書く**。答えの無い問いを放置しない |
| **R5** | 譲歩（「たしかに」「もちろん」「なるほど」「無論」） | 「たしかにA」を書いたら**必ず「しかしB」を続ける**。Bが無いなら譲歩ごと削る |
| **R6** | 要約表現（「つまり」「要するに」「結局」「このように」「言い換えれば」） | 「つまり」で始めたら、**その後件に主張の核を置く**。後件を弱く終わらせない |
| **R7** | 重視・強調（「重要」「本質」「前提」「原理」「〜こそ」「実は」「まさに」、最上級） | 「重要」と書くなら、**何がどう重要かまで書く**。語だけ置かない |
| **R8** | 筆者の主観（「〜と考える」「〜べきだ」） | 判断を書くときは**誰の判断か分かる形**にする |
| **R10** | 逆接（「しかし」「だが」「けれども」） | 前の説明のどこを修正・限定するのかを明らかにする |
| **R11** | 定義・命名（「〜とは…である」「…を〜と呼ぶ」「…を〜と名づける」） | 中心概念は**1回は定義する**。定義できないなら、その概念はまだ整理できていない |
| **R12** | 要点並列（「第一に／第二に」「まず／次に」「一方／他方」） | 独立した並列なら箇条書きを使い、因果のつながりは文章で保つ |

**R9（反語）は採らない。** 原典では「〜ではないだろうか」を強調対象とするが、**テクニカルライティングで反語は使わない。** 読み手は答えを探しに来ているのであって、問いかけを味わいに来ているのではない。番号は原典と対応させるため欠番のままにしてある。

## セクションを書き終えたら

- 読み手の問いに答え、前の説明とつながっているか。
- 対象・条件・結果や理由の対応を、読み手が推測せず説明できるか。
- 具体例を使った場合、説明中の概念と対応し、適用範囲が分かるか。
- 段落や表への分割が、理解のまとまりを壊していないか。
- なくすと理解が失われる説明と、目的に不要な詳細を区別できているか。

強調はこの理解を拾い読みでも支えるために使う。強調箇所がないことだけを理由に、必要な説明を削らない。
