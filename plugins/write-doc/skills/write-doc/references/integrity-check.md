# 正確性と読後到達点の確認

## 主張と根拠を対応させる

事実、数値、固有名詞、日付、引用、外部リンクを素材と照合する。
主張の近くに、読者が根拠を識別できる参照を置く。
原文引用は、正確な文言そのものが判断材料になる場合に使う。
すべての主張へ引用を一律に付けない。

素材にない主張を事実として補わない。
推定、仮説、未検証事項は、その状態と確認方法を明示する。
ただし、出典、観測時点、反証方法、確認先などの監査・追跡情報は、本文の一文一文にインラインで挟み込んで読者の思考の流れを邪魔しない。段落末尾の注釈、表、または節末の追跡情報へ整理する。
また、素材の事実を読者が理解しやすいよう、一般的な知識や論理で自然に解説・肉付けすることを「根拠のない捏造」と混同して過剰に委縮しない。

## 判断を変える条件を保つ

境界値、適用条件、対象範囲、例外、期限、単位を照合する。
これらを省くと読者の判断が変わる場合は、簡潔さのために削らない。
数値は単位と測定条件を近くに置く。

## 内部整合を確かめる

同じ概念の名称、状態、数値を文書内で統一する。
本文、表、図、コードの対応を確認する。
相対リンクと添付資産の参照先が保存先から到達できるか確認する。
テンプレートのプレースホルダーや執筆コメントを成果物へ残さない。

## 読者の前提で読み直す

冒頭だけで文書の答えと対象範囲が分かるか確認する。
各節が読後ゴールに必要な問いへ答えているか確認する。
読み手が次の判断または行動に必要な条件を見つけられるか確認する。

答えられない問いが素材不足による場合は、推測して埋めない。
未決事項として明示するか、完成を妨げる場合は不足情報を返して停止する。

## 削除後の意味を確認する

重複や冗長な限定を削った後、重要条件と根拠が残っているか再確認する。
読者の理解を助ける足場（Scaffolding）として機能している背景説明（Why）、動作のメカニズム、平易な言い換え、具体例を、単なる文字数削減のために削らない。
文章量や削減率を品質の代理にしない。
最終判断は、読者の理解、判断、行動が保たれているかで行う。
