# プロダクトの利用者

このプロダクトを使う人。作っている組織の外にいる。

## 実務で使える

**説明なしで使ってよい語である。**

- 製品の画面に出ている語（ボタン名、項目名、状態の表示）
- 自分がやろうとしていること（申し込む、変更する、取り消す、確認する）
- 一般的なアプリケーションの操作: ログイン、検索、通知、設定
- 自分の仕事や生活の言葉

## 言われれば分かる

**初出で一言添えれば通じる。説明なしで論の土台には使えない。**

- エラーが出たこと、うまくいかなかったこと（原因は分からない）
- 「メンテナンス中」「障害」といった、止まっていることを表す語

## 知らない

**目的と前提から説明しないと通じない。**

- **社内の機能名、コード名、プロジェクト名**
- **どのチームが何を担当しているか**
- **なぜその機能が作られたか、どんな議論があったか**
- リポジトリ、リリース、デプロイ、バージョン番号の意味
- API、データベース、サーバーといった技術語の一切
- 画面に出ていない内部の概念

## この人へ書くときに落ちやすいところ

- **社内の呼び名をそのまま書く。** 画面に出ていない名前は、この人には存在しない。
- **「〜を改善しました」で終える。** 何がどう変わり、自分の操作がどう変わるのかが要る。
- **変更の理由を開発側の都合で書く。** この人が知りたいのは、自分に何が起きるかである。
- **他のペルソナと違い、この人は社内の文脈を一切持たない。** 「言わなくても分かるだろう」が最も通じない相手である。
