# 理解の経路（既定）

**文書は、読み手の理解を「読む前」から「読んだ後」へ運ぶ一本の経路である。経路表が本文の順序と長さを決める。**

この規律が決めるのは、概念の導入順と、本文に置く節の集合である。主張と根拠は `argument`、見出しと冒頭・末尾は `structure`、節の中は `section` が決める。

## 経路表を先に作る

本文を書く前に、次の表を作る。`reader_context` の既知・未知・到達点と、`argument` で決めた主張から埋める。

| 列 | 何を書くか |
|---|---|
| 概念 | 読後の到達点に必要な概念・語。到達点に不要なものは載せない |
| 足場 | その概念を理解するのに使う、読み手が既に持っている知識か、表の上の行で導入済みの概念 |
| 導入する節 | 初めて定義・説明する節 |
| 初めて使う節 | 本文で最初に前提として使う節。導入する節と同じか、それより後 |
| 図 | 関係を図で見せるなら、その型。導入する節に置く |

表の行順が、本文の順序である。足場が無い概念は、足場になる概念を先に立てるか、その概念を落とす。

前提・反駁（`argument`）は概念ではなく条件なので、行にしない。それを使う主張の節の「足場」列に書く。

## 開示の規則

- **冒頭は、読み手が既に持つ語だけで書く。** 結論を先に置く文書でも、未導入の語で結論を書かない。書けないなら、結論を既知の語へ言い換えるか、導入を冒頭へ繰り上げる。
- **新しい語は、使う直前に導入する。** 用語集や冒頭の一覧でまとめて導入しない。まとめて導入した語は、使われる頃には忘れられている。
- **導入は1回、以後は同じ名で呼ぶ。** 言い換えや略称へ断りなく切り替えない。
- **前方参照は明示する。** 後の節で説明する概念に触れざるを得ないなら、「〇〇は後述する」と節名を添える。
- **各節の入口で、前の節との接続を示す。** 前の節で得た理解のどれを、この節で何に使うかを1文で言う。
- **視点・時点・粒度を変えるときは、変わることを言う。** 一般論から製品固有へ、全体から一部へ移るとき、黙って移らない。
- **図は、その関係を導入する地点に置く。** 説明を読み終えた後に図をまとめて置かない。

## 経路が長さを決める

文書の長さは、経路の長さで決まる。テンプレートの節数、他の文書との釣り合い、説明の丁寧さで決めない。**経路に無い概念・節・段落は、削る。** 経路にある概念が抜けているなら、短くても不足である。

文・段落の密度は `style`「量より密度」が決める。
