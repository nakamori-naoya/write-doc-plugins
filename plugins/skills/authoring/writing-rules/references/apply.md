# writing-rules の適用手順

## 読み手ができるようになることから設計する

読み手のメンタルモデルとは、対象の要素・関係・振る舞いについて、読み手が頭の中に作る理解である。品質は章や具体例の数ではなく、その理解を使って文書の目的に沿う説明・判断・行動ができるかで決まる。

1. `reader_context`が渡されたら読み、主な読み手、読む場面、既知のこと、説明が必要なこと、起こりそうな誤解、説明なしで使える用語、読後の到達点を確認する。単独使用なら依頼・資料から同じ内容を短く整理する。根拠のない前提は仮定と記し、目的を変える不足だけ質問する。
2. 到達点を支えるために、何を理解する必要があるか、その理解に何が先立つかを整理する。各節が答える読み手の問いと、次の節へ渡す理解を決める。用語の一覧だけで関係を説明したことにしない。
3. `structure`で読む順序と範囲を選ぶ。依頼された型は必要情報を取りこぼさないために使い、読み手に不要な節を埋める理由にしない。本文から外す詳細は理由と参照先・分離候補を作業記録に残す。
4. `section`で関係を説明し、必要な箇所へ具体例・比較・図・手順を置く。抽象と具体の往復は理解の飛躍を埋めるために使う。全節への例、BDD、特定の章順を必須にしない。
5. `style`の日本語と用語の基準で、読み手が知らない言葉に説明を依存させていないか確かめる。文脈と文のつながりを整え、`emphasis`で拾い読みを補助する。文数や強調の都合で因果関係を切らない。
6. `final-check.md`の問いに、本文だけを根拠に答える。前提の飛躍や誤解が残れば、表現だけでなく構成・範囲まで戻って直す。

読み手に合わせるとは、誤った前提に同意することではない。既存の理解が誤っている場合は、使える部分を足場にし、修正が必要な関係と理由を早めに示す。必要な理解の更新は明示し、唐突な前提変更を避ける。

作業用の読者整理や確認記録を、文書本文へ機械的に挿入しない。短いメールなら数行の整理と確認で足りる。

## 規律の役割

| 規律 | 何を決めるか | 及ぶ範囲 |
|---|---|---|
| `structure` | 理解の順序と本文の範囲 | 文書全体 |
| `section` | 問いへの答えと、その理解を支える説明 | セクション |
| `emphasis` | 拾い読みで浮かせる内容 | 語・節 |
| `style` | 語り口・文のつながり・用語 | 文 |
| `citation` | 出典の3点セット。緩められない | 出典 |
| `annotated-code` | コードへ注釈を振るときの規律 | コード |

強調の役は `要点` / `キーワード` / `一言でいうと` / `要約項目` の4つから必要なものを選ぶ。すべての役を使う義務はない。書き先の指定がある場合はそれに従う。

## 出典だけは緩められない

`citation` は設定で差し替えられない。出典に言及するなら、どこにあるか、そこに何と書いてあるか、だから何をしたかの3点を揃える。存在しない出典・確認していない出典を書かない。引用画像や抜粋だけを読んだ場合は、その範囲を明記し、書籍全体を確認した扱いにしない。
