# 業務知識の見本（抜粋）：定義や設定の業務

この見本は、定義や設定を保存する業務で一つの事実の置き場に迷いやすい箇所だけを、申込フォームの定義を題材に抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 制約は、値の部分ごとに名前を付けて並べた

「正しい形のフォームだけを保存できる」と一つの制約にまとめると、設問、選択肢、分岐のどれが誤っていても拒む理由が同じ名前になり、定義を書いた人はどこを直せばよいか分からない。そこで、定義の部分ごとに一つずつ制約を立てた。拒否の BDD は、それぞれ別の名前を指せる。

制約は、いつでも成り立つ形で書いた。「保存するとき、設問の番号が重なっていたら拒む」は、きっかけと結果の文であり、表の行の写しになる。

```markdown
## 制約

### 設問の番号は定義の中で一意

一つのフォーム定義の中で、設問の番号はどれも異なる。破れると、回答がどの設問への答えか決まらない。

### 選択式の設問は選択肢を2つ以上持つ

選択式の設問は、2つ以上の選択肢を持つ。破れると、申込者は選ぶ余地の無い設問に答えさせられる。
```

## 表は保存する行いの二行にし、分かれ目を検査の結果という計算にした

定義は保存するたびに新しい版ができ、できた版は変わらない。移り変わる在り方が無いので、状況は持たないと書いた。表は保存の二行である。二行を分けるのは、対象の状況ではなく、きっかけが運ぶ定義の中身が制約を満たすかである。それを「検査の結果」という区分の計算にし、二行の分かれ目をその答えで書いた。答えのどれにも行がちょうど一つあることを、検査が確かめる。制約を破る定義は保存されず、対象として存在しないので、「不正な定義」という状況は作らなかった。

一つの定義が制約をいくつも破ることがある。管理者が一度に全部を直せるよう、拒む理由の示し方を「当たったすべて」と宣言した。分岐の先が存在しないと、その先が後ろかどうかは判定できないので、「分岐の先は後ろの設問」に判定の前提を置いた。分岐の先が無い定義では「分岐の先は定義の中にある」だけが当たり、一覧が一つに決まる。

````markdown
## 制約

### 分岐の先は定義の中にある

設問の分岐の先は、同じフォーム定義の中の設問である。破れると、申込者がどこへ進むか決まらない。

### 分岐の先は後ろの設問

設問の分岐の先は、その設問より後ろに並ぶ設問である。破れると、申込者が同じ設問へ戻り続け、申込を終えられない。

判定の前提：分岐の先は定義の中にある

## 状況

この業務は状況を持たない。フォーム定義の版は、できた後に変わらない。

## 計算

### 検査の結果

列挙：検査の結果 = 通る | 通らない

| 当たった制約 | 答え |
|---|---|
| 無い | 通る |
| 一つ以上 | 通らない |

## 行動・出来事と判断

同じフォームへのきっかけは、確定した順に一つずつ表に当てはめる。

拒む理由の示し方：当たったすべて

| いつ | 誰が | 何をすると | 何が起きる | どの決まりによるか |
|---|---|---|---|---|
| いつでも | フォームの管理者 | フォーム定義を保存する（検査の結果が通る） | 新しい版ができ、「フォーム定義を保存した（FormDefinitionSaved）」が起きる | 検査の結果 |
| いつでも | フォームの管理者 | フォーム定義を保存する（検査の結果が通らない） | できない。何も変わらず、当たった制約がすべて一つの一覧で示される | 設問の番号は定義の中で一意、選択式の設問は選択肢を2つ以上持つ、分岐の先は定義の中にある、分岐の先は後ろの設問、検査の結果 |

## BDD

### [BDD-004] 自分より前の設問へ分岐する定義は、保存できない

```gherkin
Given: フォーム F-0001 の定義は、設問1、設問2、設問3をこの順に持つ
  And: 設問3は、「はい」を選ぶと設問1へ分岐する
When: フォームの管理者がこの定義を保存する
Then: 保存できず、新しい版はできない
  NOTE: Rule: 分岐の先は後ろの設問
    Reason: 設問1は設問3より前に並んでいる
```

### [BDD-005] 二つの制約を破る定義は、二つとも一度に示す

```gherkin
Given: フォーム F-0001 の定義で、設問1と設問2が同じ番号1を持つ
  And: 選択式の設問2は選択肢を1つだけ持つ
When: フォームの管理者がこの定義を保存する
Then: 保存できず、「設問の番号は定義の中で一意」と「選択式の設問は選択肢を2つ以上持つ」が一つの一覧で示される
  NOTE: Rule: 設問の番号は定義の中で一意
    Reason: 二つの設問が番号1を持つ
```
````

## 定義を使う側の決まりは、持ち主の資料に任せた

新しい版を保存したとき、前の版で答えている途中の申込をどうするかは、定義の形ではなく申込の一生の決まりである。主語は申込なので、申込の業務の資料が持つ。この資料では、核の「この業務が決めないこと」に持ち主を挙げるだけにした。ここに書くと、同じ決まりを二つの資料が持ち、片方だけが直される。

```markdown
この業務が決めないことと、その持ち主は次のとおりである。

- 新しい版ができたときの、答えている途中の申込の扱い：[申込の業務知識](../application/業務知識.md)
```
