# API テストシナリオの見本（抜粋）

この見本は、API テストシナリオの資料で判断が分かれやすい箇所だけを、図書館の貸出を題材に抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 呼び手は項目で名乗らせず、呼び手でない当事者は項目にした

窓口の職員が呼ぶ「本を借りる」では、借りる利用者は職員とは別の当事者なので、利用者番号を要求の項目にした。操作した職員が誰かは横断的関心事の設計が識別するので、項目に置かなかった。利用者が自分の端末から借りる題材なら、借りる人が呼び手になり、利用者番号も項目から消える。

| 項目 | 意味 | 必須 | 出どころ |
|---|---|---|---|
| 利用者番号 | 本を借りる利用者 | 必須 | 業務知識「利用者番号」 |
| 資料番号 | 借りる本 | 必須 | 業務知識「資料番号」 |
| 貸出番号 | 生まれた貸出 | 必須 | 業務知識「貸出番号」 |
| 返却期限 | 生まれた貸出を返す期限 | 必須 | 業務知識「返却期限」 |

## Code は拒む理由ごとに一行にし、確定したか分からない Code には確かめ方を書いた

延滞と貸出上限はどちらも同じ Code になるが、利用者が次にすることが違うので、行と文言を分けた。時間切れは、貸出が生まれたかを呼び手が区別できないので、送り直す前に利用者の貸出の一覧で確かめると書いた。書かなければ、呼び手は二重の貸出か取りこぼしのどちらかを選ぶしかない。

| 拒む理由 | 分類 | Code | 公開の文言 | 再試行の可否と、確定したか分からないときの確かめ方 |
|---|---|---|---|---|
| 延滞の貸出がある利用者が本を借りる | 業務の拒否 | `FAILED_PRECONDITION` | 延滞している本を返すと借りられます | 延滞の本を返すまで、送り直しても同じ結果になる |
| 貸出上限に達している利用者が本を借りる | 業務の拒否 | `FAILED_PRECONDITION` | 借りられるのは5冊までです | 一冊返すまで、送り直しても同じ結果になる |
| 時間切れ | 一時的な失敗 | `DEADLINE_EXCEEDED` | 処理が完了したか確認できませんでした | 利用者の貸出の一覧に同じ資料番号の貸出中が無いと確かめてから送り直す |

## 境界には Code を確かめる代表例だけを置き、境界値は下のレベルへ送った

貸出上限は、5冊借りている利用者の拒否を一例だけ置いた。4冊なら借りられることは、境界を通さなくても同じ判断を再現できるので、業務判断のレベルへ送った。延滞の拒否は Code が同じでも文言が違うので、このシナリオに表の行として詰めず、別のシナリオにした。

### [BDD-003] 5冊借りている利用者には貸さず、貸出上限の文言を返す

```gherkin
Given: 利用者 U-0001 は本 B-1001〜B-1005 の5冊を借りていて、延滞の貸出は無い
When: 窓口が2026年10月1日に、利用者 U-0001 に本 B-1006 を貸す
Then: `FAILED_PRECONDITION` と「借りられるのは5冊までです」が返る
  And: 利用者 U-0001 の貸出の一覧は、B-1001〜B-1005 の5件のままである
```

拒否の業務の理由が、呼び手の見る Code と文言へ変わる箇所を確かめる。主担当は公開インターフェースの Medium である。4冊なら借りられる境界は、業務判断のレベルが業務知識の BDD-002 で確かめる。

## 送った項目は、観測するレベルを一つに決めた

同じ本を二人が同時に借りたときの結果は、公開の操作を並べても順が決まらず、境界では観測できない。そこで観測するレベルを永続化の一つに決め、コマンドデータモデルの BDD-011 を指した。送り先を二つ並べると、どちらのテストもその結果を観測しないまま残る。

### 同じ本を二人が同時に借りる

永続化のレベルで観測する。コマンドデータモデルの BDD-011 が、二つの貸出の書き込みのうち一つだけが残ることを確かめる。
