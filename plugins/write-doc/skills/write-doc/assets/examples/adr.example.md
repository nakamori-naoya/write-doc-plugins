# ADRの見本（抜粋）

この見本は、ADRで判断が分かれやすい箇所だけを抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 冒頭は、選んだものを先に言い切る

後任が最初に知りたいのは何を選んだかなので、冒頭の最初の文で選んだものを言い切り、承認の状態と決めた人はその後に置く。状態から書き始めると、読み手は二文目まで何の決定かが分からない。提案中の記録なら、最初の文は提案する案になり、続けて誰の決定を待っているかを書く。

採らない書き出し：

> この決定は、2026年8月28日に技術責任者とDB担当が承認した。

採る書き出し：

> 同じ会議室で時間帯が重なる予約の登録を、DBの排他制約で拒否する。2026年8月28日に技術責任者とDB担当が承認した。

## 比べた候補は、同じ軸で性質だけを並べる

候補が四つあったので表にし、セルには各候補の性質だけを書いた。採否とその理由は表の後の文章で書く。候補が二つなら表にせず段落で比べる。

| 候補 | 時間帯の重なり | 同時要求への対応 |
|---|---|---|
| 事前の空き確認だけ | 照会時点では確認できる | 確認後の競合が残る |
| DBの排他制約 | 同じ部屋と時間範囲の重複を条件にできる | 制約のある書込先で拒否する |

> 事前の空き確認だけでは、登録の時点での保証にならないので採らない。

## 見直す条件は、観測できる変化で書く

「必要に応じて見直す」では後任が見直す時を決められないので、どの前提が崩れたら基準が変わるかを書いた。未計測のことは推測で埋めず、未検証と書く。

> 一つの会議室を同時に複数顧客へ販売する商品へ変わると、「重なりを一律に拒否する」という基準が変わる。負荷時の待ち時間はこの記録では未検証である。
