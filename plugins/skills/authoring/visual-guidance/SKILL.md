# choose-visual

**図の正体は、文章で順に読む関係を、位置・形・面積・個数・距離・線・色へ写して同時に見せることである。** 飾るためではなく、主要な主張を速く正確に理解させるために使う。

## 0. 配布物を確かめる

<!-- BEGIN shared:skill-entry/root-only -->
```bash
PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-/absolute/path/to/this/plugin}"
bash "${PLUGIN_ROOT}/scripts/prepare.sh" --root-only >/dev/null || exit 2
```

**このコマンドは説明例ではない。必ず実行する。** 失敗したら先へ進まない。
<!-- END shared:skill-entry/root-only -->

## 1. 図が答える問いを決める

依頼、本文、素材から読み手・目的・主要な主張を取る。文章より図の方が関係を速く理解できる箇所を選び、図が答える問いを疑問文1つで書く。

次をすべて満たす候補だけを残す。

1. 資料の主要な主張へ直接つながる
2. 関係・偏り・境界・変化・波及範囲のいずれかを見せる
3. 位置・形・面積・個数・距離・線・色のいずれかに意味を持たせられる

候補が無ければ、図を作らず「図にすると理解が速くなる関係が無い」と返す。**図を必須にするか、図が無い結果を許すかは呼び出し元の責務であり、このスキルは判定しない。**

## 2. 目的に合う型を選ぶ

[目的別の選択表](references/patterns.md)を読み、問いに合う型を1つ選ぶ。インフラの配置を説明したいのにシーケンス図を選ぶなど、問いと型を取り違えない。

コードやシステムの資料では、必要に応じて[技術資料の図](references/technical.md)も読む。

構成図、スイムレーン業務フロー、CI/CDなど、境界・レーン・凡例・注記を固定配置して資料品質で見せる図では、[画像で作る技術図](references/image-diagrams.md)を読み、画像生成を優先するか判定する。単純な静的関係ならコードネイティブな図を選ぶ。

## 3. 図の設計を返す

各図について、次の3役を返す。

| 役 | 返すもの |
|---|---|
| 図の主張 | 図だけを見る人に持ち帰らせる1文 |
| 図の型 | 選んだ型と、その型が問いに合う理由 |
| 図の内容 | 要素、配置、線、強調、凡例と、それぞれが意味するもの |

加えて、本文のどの主張の直後へ挿入するかを指定する。本文に無い事実を足さず、数値と名称を本文・原典に一致させる。

画像生成を選んだ場合は、`図の内容`へ使用する参考画像、キャンバス、固定配置、表示文字列、矢印の意味、Scope・前提・対象外、生成後の照合項目まで書く。画像生成機能が無ければ、画像を作ったと報告せず、この生成仕様を返して停止する。

## 4. 品質を確認する

図案を作った後に[quality.md](references/quality.md)を読み、全項目を確認する。
