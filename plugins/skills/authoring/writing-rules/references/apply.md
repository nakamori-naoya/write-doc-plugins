# 規律の適用手順

**読み手の前提と到達点から主張・経路・構成を決め、その順で書き、本文だけを根拠に読後の判断ができるかを確かめる。** 品質は章や具体例の数ではなく、読み手が本文から組み立てた理解で、文書の目的に沿う説明・判断・行動ができるかで決まる。

1. **読み手と到達点を確認する。** `reader_context` と、あれば `decisions`（settle で合意した決定と未決）を読む。主な読み手、読む場面、既知のこと、説明が必要なこと、起こりそうな誤解、説明なしで使える用語、読後の到達点、`premises`・`stance`・`history`・`verification_means` を確認する。単独使用なら依頼・資料から同じ内容を短く整理する。無い項目は、write-doc の記録の契約（`references/reader-contract.md`）にある各項目の既定で扱い、仮定と記す。単独使用では目的を変える不足だけを質問し、write-doc から呼ばれた場合は質問せず、未確認として本文に残す。
2. **主張を決める**（`argument`）。文書の主張を1文に決め、各節の役（根拠・限定・行動）と、主張ごとの決定的根拠を決める。経緯は `history` に従って前提へ畳む。主張が決まらないうちに経路表を埋めない。
3. **経路表を作る**（`path`）。到達点に必要な概念を、足場・導入する節・初めて使う節・図とともに並べる。この表が本文の順序と長さを決める。write-doc から呼ばれた場合は `reading_path` として残す。
4. **構成を決める**（`structure`）。冒頭・見出し・末尾・本文に残す情報を決める。テンプレートの扱いは content-types の SKILL.md §5 に従う。
5. **各節を書く**（`section`）。自分が観測・計測・推定した値やその比較を載せるなら `evidence`、出典に言及するなら `citation`、コードに注釈を振るなら `annotated-code` を適用する。
6. **語と文を整える**（`style`、`terminology`、`emphasis`）。`terminology` の判定手順を、日常語でない語すべてへ1語ずつ適用する。
7. **読み手として確かめる**（[final-check.md](final-check.md)）。本文だけを根拠に問いへ答える。前提の飛躍や誤解が残れば、表現だけでなく経路・構成・範囲まで戻って直す。

読み手に合わせるとは、誤った前提に同意することではない。既存の理解が誤っている場合は、使える部分を足場にし、修正が必要な関係と理由を早めに示す。

作業用の経路表や確認記録を、文書本文へ挿入しない。
