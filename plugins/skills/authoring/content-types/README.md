# content-types

**誰に何を届けるかを決める。** 同梱ペルソナから読み手を1人選び、読後の到達点を問いへ落とし、そこから文書の型を1つ選ぶ。

**順序を入れ替えない。** 読み手 → 到達点 → 型である。型を先に決めると、型が持つ節を埋めるために内容を集めることになる。

**規律も媒体も知らない。** どう書くか・どう出すかは、それぞれ別の関心である。

## 使う

```
/pick-content-type      読み手と到達点を決めて、型と骨格を取る
```

## 読み手ペルソナ（5人・固定）

| ペルソナ | 一言でいうと |
|---|---|
| プロダクトマネージャー1年目 | 技術用語が一つも通じない。前提を何も置けない |
| プロダクトマネージャー3年目 | 数字で判断する。関わった範囲の技術語だけ分かる |
| バックエンドエンジニア1年目 | 担当範囲のコードは読める。設計と運用は知らない |
| バックエンドエンジニア5年目 | 設計から運用まで通せる。専門外は「言われれば分かる」 |
| プロダクトの利用者 | 社内の文脈を一切持たない。画面の語だけ知っている |

各ペルソナは語を3段階（実務で使える／言われれば分かる／知らない）で持つ。**この5人以外を作らない。** 選び方は[personas](references/personas.md)。

選んだペルソナは、write-docの最後の判定工程で**別の読み手役がなりきる相手**になる。

## 28種のカタログ

「選び方」を上から順に判定する。**決まった型の詳細だけ**を読む（全部読まない）。

| 群 | 型 |
|---|---|
| プロダクトの方向と経路を決める | Product North Star / Product Strategy |
| 業務を確定する | 業務知識・コアドメイン |
| 複数場面を通じた目的達成を共有する | ユーザー目的達成BDD |
| データを永続化する | RDB論理設計 / RDB物理設計 |
| 追う | 期間ダイジェスト / 決定ログ / 論点台帳 |
| 学ぶ | スタートガイド / チュートリアル / ハウツー / コンセプト / オンボーディング |
| 引く | API リファレンス / 用語集 / トラブルシューティング / Runbook |
| 決める | ADR / デザインドック / ポストモーテム / リリースノート |
| コードと入口 | コードコメント / README / ランディングページ / 実装解説（PR） |
| コードを説明する | コード地図（マクロ） / コードリーディング |

**コードを説明する型は3つあり、読み手の問いで分かれる。** どこに何があるか（コード地図）／この処理はどう動くか（コードリーディング）／この変更で何が変わったか（実装解説（PR））。**混ぜない。** 上の群表では、実装解説（PR）を入口の型と同じ行に置いているが、説明の型としてはこの3つで一組である。

各型に**読み手・読み手の状態・目的**が付く。専門領域の内容の正しさや作業方法は呼び出し元が与え、content-typesは補わない。

**テンプレートは埋める枠ではない。** 節の候補と境界を示す参考資料であり、本文の構成は経路表が決める。カタログの「固定見出しを持つ型」に載っている型だけ、見出しと順序が不変条件になる。

各テンプレートの節にはHTMLコメントで**「書く内容」と「書かない内容」**を持たせる。見出しだけを渡して内容を推測させない。コメントは執筆時の境界であり、本文を満たしたら成果物から削除する。`bash scripts/validate.sh`が、全テンプレートの見出し直下にこの境界があること、同じ節へ二重に置いていないこと、テンプレートの見出しが対応する記載例に揃っていることを検査する。

## 設定

```yaml
# <repo>/.harness-plugins/content-types.config.yml
version: 1
default_type: concept           # 型が特定できないときの既定
instructions:
  selection:
    directive: catalogの選び方を上から判定し、型を1つだけ選ぶ
```

このファイルだけで完結させる。personal設定や同梱既定から不足キーは補われない。

テンプレートはプラグイン同梱の28種だけを使う。テンプレートと記載例の対応は`assets/template-examples.yml`を正本とし、選んだ型に対応する両方を読む。記載例はテンプレートを埋める前に全文を読む。リポジトリ独自テンプレート、独自の型、同名テンプレートの上書きは受け付けない。旧`templates_dir`が残っていればresolverが停止する。

**`default_type` に対応するテンプレートが無ければ止まる。** 存在しない骨格を探しにいかせない。

## しないこと

- 文章を書かない
- 媒体の書式を決めない
- 依頼や専門型の成果契約で必要な見出し・順序は保持する。それ以外は、型の目的と必要情報を保ちながら読み手に合わせて省略・統合・並べ替えできる。必須項目の「なし」と「未確認」は区別する
