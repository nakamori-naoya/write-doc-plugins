# 利用負荷の見本（抜粋）

この見本は、利用負荷の資料で判断が分かれやすい箇所だけを、会議室の予約サービスの題材から抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 平均は式と時間窓を書き、ピークは別の根拠で置く

平均は月の総量を暦の時間でなく活動時間で割ったので、その式と仮定を書いた。ピークは平均に一般の倍率を掛けず、電話台帳と聞き取りから置いた仮説にした。ピークの根拠が無い題材なら、ピークを作らず未決にする。

> 月間の活動時間は25営業日×4,000秒=10万秒と仮定した。検索150万件÷10万秒=15件/秒が算術平均で、容量判断には1分ピークの120件/秒を使う。どちらもRoomFlowの実測値ではない。

## 偏りは、増える理由で二つに分ける

人気の枠の公開直後の集中は、短い時間に操作が集まる型なので到着率で表した。通知は、操作の数は少なくても一件の状態変更が二か所へ届く型なので配送数で表した。後者は操作の上限では抑えられないので、規模を縮めても残る特性として分けて渡す。

> 一件の状態変更は二配送へ増幅する。利用者数を縮小しても、同じ枠への競合と一操作あたりの通知先数は同じ比率で縮小しない。

## 保持は値だけを持ち、守ることは品質要求へ渡す

容量を見積もる保持期間は計算の仮定であり、業務上の保持期限とは意味を分けた。通常の一覧から外す時期や消去で守ることは、品質要求の資料が持つ。

> 保持期間は、容量を見積もるための値である。予約の7年は仮に置いた年限で、法務確認の結果で決める。

## 追跡の表には、仮定の根拠と状態を一組で置く

同じ行の中でも、合意済みの部分と仮説の部分を分けて書いた。通知先が二人であることは合意、その率は仮説である。
