# システム構成の型

## システム構成

**読み手**: そのシステムを変更・運用するエンジニア
**目的**: いま何がどこで動き、何と通信し、どこに何が残り、どこが境界かを、照合できる名前で宣言する
**成功条件**: 読み手が本文だけで「この変更はどの要素に影響するか」「この要素が落ちたら何が止まるか」を答えられる

現在の構成だけを書く。変遷・試した案・選定理由は書かず、決定の理由が要るならADRへリンクする。手順はハウツーガイドへ、テーブル定義はRDB論理設計・RDB物理設計へ、業務の決まりは業務知識・コアドメインへ分ける。

構成の正しさ（実際にその名前で動いているか）は、入力された観測事実と観測時点で判断する。この文書型は構成を調べず、同梱の骨格と記載例だけを示す。
