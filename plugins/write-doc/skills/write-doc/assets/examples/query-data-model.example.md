# クエリデータモデルの見本（抜粋）

この見本は、クエリデータモデルの資料で判断が分かれやすい箇所だけを、図書館の貸出を題材に抜き出したものである。題材の値や言い回しは写さず、どこで何を判断したかを見る。節の構成はテンプレートが持つ。

## 足りない事実は、ここで足さずに持ち主のテーブルを組み合わせた

借りている本を同じ返却期限の中で借りた順に並べるには、借りた時点が要る。`loans` には無いが、`loan_base_events` の借りた事実に `occurred_at` があるので、列を足さずに結び付けた。持ち主のどのテーブルからも導けなかったなら、この資料で作らず、コマンドデータモデルへの差し戻しとして未決に書く。

| 読むテーブル | 持ち主の資料 |
|---|---|
| `loans` | [図書館の貸出のコマンドデータモデル](../貸出/command-data-model.md) |
| `loan_base_events` | [図書館の貸出のコマンドデータモデル](../貸出/command-data-model.md) |

> `loans` から、その利用者の `status` が `lent` か `overdue` の行を選び、`due_on` の昇順に並べる。同じ返却期限なら、`loan_base_events` の `event_type` が `lent` の行を `loan_id` で結び付け、その `occurred_at` の早い順にする。

## 業務知識が並び順を決めていない読み取りは、ここでも決めなかった

延滞にする貸出を探す読み取りは、どれを延滞にするかだけが業務の決まりで、並べる順は業務知識が決めていない。そこでこの資料でも順を決めず、一度に読む件数や index は物理設計への申し送りに書いた。利用者に見える一覧で並び順が業務の決まりなら、逆にそれを BDD で確かめる。

## 「0件が返る」と「拒まれる」を書き分けた

返却済みの貸出しか無い本の借り手を確かめると、利用者に見える結果は空の一覧で、拒否ではない。対象の行が無いこと自体を業務知識が拒む理由にしているなら、取得結果を拒む理由の表にする。

### [BDD-004] 返却済みの貸出しか無い本は、借りている利用者が0件で返る

```gherkin
Given: 本 B-1004 の貸出 L-004 は返却済みである
When: 窓口が2026年10月12日に本 B-1004 を借りている利用者を確かめる
Then: 借りている利用者は返らない
```
